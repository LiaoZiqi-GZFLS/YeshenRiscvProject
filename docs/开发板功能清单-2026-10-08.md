## 2. 功能清单（分层）

### 2.1 CPU / SoC
- **VexiiRiscv RV32**：`isa : rv32imac`、`mmu : sv32`（Sv32 + TLB + PTW）
- 2 译码/lane、I$/D$ L1、GShare+BTB+RAS 预测
- **3 个 AXI4 主口**：取指(RO) / LSU(RW) / 无缓存 IO
- 内存：DDR3（紫光 IP，200H 版），Linux 可见 **`MemTotal 249,760 kB`**（≈244 MiB）
- 时钟：板级 PLL `clk_in 27 MHz → cpu_clk 100 MHz`；DDR 侧 125 MHz 取 IP 自己的 `core_clk`

### 2.2 存储
- **SPI TF/SD 装载器**（`SdLoader` + `SdSpi` + `SdUartReport`）：从卡读四镜像并按装载表搬到 DDR 固定地址
- DDR3 512 MiB 窗口（`0x80400000` 起，按 Linux 启动日志的 memory node）；★ H2/H2b 后其中
  `[0x80400000, 0x82000000)` 是 NPU arena 保留区（reserved-memory/no-map）⇒ **内核可用 RAM 从
  `0x82000000` 起**（`MemTotal` 会相应少约 28 MiB；`/proc/iomem` 的 System RAM 也从此起）

### 2.3 软件栈
- **OpenSBI 1.6**（XLEN=32，控制台 `uart8250`，`NAX_CONSOLE_BAUD=115200`）
- **Linux 5.10.1**（SpinalHDL/linux `dev` 分支，rv32imac；**按 C89 编**）
  当前板上实测构建串：**`#2 SMP Thu Oct 8 00:49:59 CST 2026`**
- **buildroot 2025.02.18** rv32imac 的 busybox **initramfs**（rootfs 每次上电从卡载入，运行期改动不持久）
- 用户态：`busybox 1.37.0`（wget / tftp / telnet / crond / syslogd / klogd …）、`micropython`、`dhrystone`、**`dropbear` sshd**、`devmem`

### 2.4 控制台（16550）
- 16550 @115200（**16 深 RX FIFO**；TX 亦已补 FIFO）
- **可交互登录**（`root`/`yeshen`），回显与长输出正常
- **已关软件流控**：`/sbin/getty_ixon`（exec getty 前 `stty -ixon`）+ `/etc/profile` + 主机工具开口补 `^Q`
  ⇒ 灌 `^S` 不再让控制台静默

### 2.5 网络（LiteEth + RGMII）
- **LiteEth MAC 黑盒**：`dw=32`、`with_sys_datapath=True`、`endianness=little`、**rx 4 / tx 2 槽**（每槽 0x800 B）
- **厂家 RGMII PHY 网表**（`eth_stack_2_11/source/rgmii_interface.v`）+ **运行期可调延迟**（`dly_txclk`/`dly_rx`，原值 100/247）
- 驱动：主线 `litex_liteeth.c` 的移植补丁 —— **排干循环**（一次中断把 pending 的帧搬干）
- DTS：`litex,rx-slots=<4>`、buffer 窗口 `0xF0008000..0xF000AFFF`（0x3000，0x4000 对齐）

## 3. 本会话定位并修掉的四个真根因

| # | 根因 | 判据（板级） | 修法 |
|---|---|---|---|
| 1 | PHY 域 **`ResetSync` 自锁**（复位把自己清零 ⇒ 链填不满 ⇒ 两域永久复位） | `rxcHi=rxcLo=1` 但 MAC 数据通路全死 | 同步链 `reset_less=True`（黑盒重生成） |
| 2 | LiteEth **`dw=8 + with_sys_datapath`** ⇒ TX 的 CDC 饿空（100 MB/s 追不上 125 MB/s） | **`txRunMax = 4`**（应 ≥68） | `dw=32` + `endianness=little` + 槽口 32 bit |
| 3 | **线速突发的上限 = MAC 在飞缓冲（槽数）**；**驱动排干 = 消费速度**（两个杠杆） | 50 帧连发只收 ~4（= 槽数）；中断数 ≪ 帧数 | rx 槽 2→4 + 驱动 **待处理帧排干循环** |
| 4 | **控制台静默 = `IXON` 软件流控**（RX 本稳） | 静默时 `LSR=0x60`/`IIR=0xC1`/`IER=0x05`（硬件空闲）；灌 `^S` 停、`^Q` 救 | `getty_ixon` + `/etc/profile` + 主机补 `^Q` |

## 4. 已知边界 / 开放项（都留档，勿重复踩）

1. **线速背靠背突发会丢**：50 帧连发只到 ~4（= rx 槽数）。上限是**硬件在飞缓冲**，参数调不动
   —— 外设窗只有 64 KB，而一个 2 KB 槽 × 32 个就吃满。要彻底解决得换 **DMA 环 / 更大的 RX 缓冲设计**。
2. **不要用 NAPI**：试过一版，`liteeth_poll` 返回 `budget`（= NAPI 语义"还有活"）+ 判空依据
   （`WRITER_LENGTH != 0`）恒真 ⇒ **softirq 风暴把板子挂死**。已干净回退，坏版留档
   `sim/reglogs/patch_napi_broken_bak.diff`。§19 的排干循环已够用。
3. **ssh 残余抖动**受第 1 条影响（TCP 靠重传救回；单次 2–6 s，偶发贴超时）。长输出会话偶发卡死
   与"大帧 TX"**无关**（§21 已证 144 KB 连发 OK），更可能在会话/互操作层（见 §1 的 ssh 行 KEX 说明）。
4. **FPGA 配置易失**：断电/换卡后串口连 SDR 行都没有 ⇒ **先重烧再排查**（≠ 卡没插好）。
5. **J25 卡座接触抖**：判据 `misoHi=0`；重插即可，别怀疑镜像。
6. **控制台会话要口令**；板内判据命令**要短**（长行偶发坏字节，未复现，暂记开放小项）。
7. **登录提示符不回声**：在 `buildroot login:` 发 `\r` 得 0 字节是正常，别当卡死。
8. ⚠️ **GMII 观测窗（`0xF000B0xx`）的计数器已饱和**：`txBytes/rxBytes` 是 **16bit**、`*RunMax` 是 **8bit**，
   早就停在 `0xFFFF / 0xFF` ⇒ **读数恒为 0 增量、不能再当判据**。做收发判据一律改用
   **`/proc/net/dev`（64bit）** ＋ 主机侧网卡计数（两侧独立）。⚠️ 历史上"板发大帧发不出去"的误判
   很可能就源于把**饱和值**当成"没发出"。
8. ⚠️⚠️ **板 → 主机「大帧 / 批量」TX 是坏的（2026-10-08 新发现，开放项）**
   - 实测**陡壁**（ssh 从板上拉数据，看主机收到多少）：

     | 请求 | 100 B | 1000 B | **1400 B** | 1500 B | 2000/4000/10000 B |
     |---|---|---|---|---|---|
     | 主机收到 | 100 ✓ | 1000 ✓ | **0** ✗ | **0** ✗ | **全 0** ✗（各 25 s 超时） |

   - **RX 方向同尺寸完全正常**（1400 B 载荷 = 1442 B 帧，板 `rx_packets` **10/10**、`rx_bytes +14480`）
     ⇒ **TX 专属**，不是链路 / PHY / 卡。
   - 影响面：`ssh board cat <大文件>`、任何"板发 >1 KB"的场景，
     **以及所有 PQ KEX（sntrup761 握手报文 >1 KB）** —— 见 §1 的 ssh 行。
   - **两处此前说法要撤回**：① "板→主机 TCP 载荷 PASS" 那条判据实际测的是**进板**方向；
     ② "TX 稳" 只对**小帧**成立（ARP/ICMP/ACK/小 HTTP 响应），大帧/持续多发**从来没测过**，
     补测即发现是断的。③ 早期几次"ssh 输出为空"我曾归因成"WSL 管道截断" ✗ —— 真因就是本条。
   - 嫌疑面（**未查**，下一轮）：2 个 tx 槽的"停队列 / 唤醒"是否漏一次（`READER_EV_PENDING` 也是 sticky）、
     MAC reader 的 frame length 与 TX SRAM 深度、driver `slot_size`(0x800=2048) 与 MAC 实际槽深是否一致。

## 5. 复现入口（一条链）

> **Phase 7 三件套**：`scripts/build_all.sh`（一键构建）/ `scripts/flash_and_verify.py`（一键烧板+验启动）/
> `docs/board_bringup.md`（bring-up 手册：前置、流程、判据、故障排查表、命令速查）。
> 下面是最底层的手工命令，脚本封装的就是它们。

```bash
# 0) 前置：WSL 够不到 Windows 的 Clash（只绑 127.0.0.1）⇒ 先在 Windows 起 relay
python scripts/win_proxy_relay.py            # 172.21.128.1:7898 -> 127.0.0.1:7897

# 1) 出带（从零：JAG 网表 → dev_map → PnR → 比特流）
YESHENMINI_PNR_TAG=m9 YESHENMINI_PNR_FRESH=1 \
  /c/Pango/PDS_2025.2-ads/bin/pds_shell.exe -file D:/code/PDS/VexiiYeshenLinux/pds/run_pnr_yeshen.tcl

# 2) 重建镜像（改过内核补丁/overlay/DTS 时必须带 REBUILD_PKGS=linux 让它 dirclean+rebuild）
wsl -e bash -lc 'cd /mnt/d/code/PDS/VexiiYeshenLinux && REBUILD_PKGS="linux" bash scripts/build_images.sh'

# 3) 打卡镜像 + 写卡（写卡需管理员；脚本自带 GUARD 与 SHA256 回读校验）
python sim/mk_sd_image.py --out sw/images/sd.img \
  --entry 0x80000000=sw/images/fw_jump.bin --entry 0x82000000=sw/images/Image \
  --entry 0x82F80000=sw/images/linux.dtb  --entry 0x83000000=sw/images/rootfs.cpio
powershell -File sim/board/write_sd.ps1 -Disk 2 -Letter E      # ⚠️ 先用 Get-Disk 核对盘号

# 4) 上板烧写（cdt_js 自报端口；flash 脚本默认 TAG=m9）
/c/Pango/PDS_2025.2-ads/bin/cdt_js.exe &
/c/Pango/PDS_2025.2-ads/bin/cdt_cfg_shell.exe -file D:/code/PDS/VexiiYeshenLinux/pds/flash_yeshen.tcl

# 5) 判据
python -u scripts/uart_login_pw.py COM7 115200 yeshen     # 控制台登录（带口令）
python -u scripts/guest_cmd.py COM7 115200 "grep eth0 /proc/net/dev"
python -u scripts/eth_dbg_read.py COM7 115200 2           # GMII txRunMax/rxRunMax
python -u scripts/eth_udp_e2e.py COM7 115200 192.168.1.110 # burst vs paced
python -u scripts/uart_stress_probe.py COM7 115200 200 400 # 串口 fe/oe/pe 定性
MSYS_NO_PATHCONV=1 wsl -e bash -lc 'SSH_ASKPASS=$HOME/askpass.sh SSH_ASKPASS_REQUIRE=force \
  ssh -o KexAlgorithms=curve25519-sha256 -o HostKeyAlgorithms=ssh-ed25519 root@192.168.1.110 "uname -a"'
```
