## 1. 目标与范围

**C4 是什么**：让硬件**第一次能吃下真模型并算完整一帧** —— 即
**① 转换器**（YuNet ONNX → 描述符表 + 权重 blob + 每层量化参数）、
**② 通道覆盖**（真网的 `C=3/16/32/64/1/4/10`、`C_in≠C_out`、20 层 depthwise）、
**③ 权重从 DDR 批量装载**、**④ 宿主侧输入/输出与前后处理**。

**C4 不是什么**：不做帧率/争用实测（C5）；不做摄像头（Y5）；不改 C3 的调度语义（描述符表口径冻结）。

## 2. 现状 vs 真模型：缺口（真表口径，`desc_table.py` 冻结直方图，67 项载荷）

| 算子 | 真表 | 本代 RTL | 缺什么 |
|---|---|---|---|
| conv3x3 | 7 | ✅ 仅 **8→8** | `C_in=C_out=8` 之外的所有形状 |
| conv1x1 | 26 | ✅ 仅 8→8 | 同上 |
| **depthwise** | **20** | ❌ 无单元（只有 group=8 的 8 通道档） | `0x03` 单元 + 宽 C |
| maxpool / resize / add / sigmoid | 4/2/2/6 | ✅ | — |
| Transpose / Reshape | 12 / 12 | ❌ | 需**折进寻址**（转换器产出的是地址步长/序） |
| Relu | 15 | ✅ 折进生产者尾声 | — |
| （Concat） | 0（YuNet 不用） | ❌（`0x12` 未实现） | **不阻塞** |

**两大缺口**：**通道覆盖**（切片 `require(C_IN==8 && C_OUT==8)`）与**转换器**（不存在）。

## 4. **已裁决（2026-10-10）**：用户采纳以下三项推荐

### 4.1 通道覆盖怎么做？→ **已定 (b) 8 通道多趟 + 跨趟累加**
| 方案 | 内容 | 后果 |
|---|---|---|
| **(a) 可配置宽切片**（按最大 C 配阵列） | 一张网表支持任意 `C`；阵列按 `C=64` 配 ⇒ 每片 `64×8`=512 MACs，×8 片 | **面积爆炸**：8×512 APM ≫ 740 ⇒ 不可行（同一"1152 乘法器 vs 740 APM"的死因） |
| **(b) 8 通道多趟 + 跨趟累加**（**推荐**） | 硬件保持 8×8；宽层拆成 `ceil(C/8)` 趟；跨趟**累加**：片上部分和缓冲 **或** DDR 读-改-写 | 面积不变；**代价是额外 DDR 往返 + 帧时↑** ⇒ 必须先量化（见 C4-G2） |
| (c) 折中：阵列 8→16 | `C=16` 一趟；更宽仍多趟 | 面积 ×4（APM 273→~500+，CLMA 91% 已满 ⇒ 有风险） |

**已定 (b)**（用户裁决）。理由：面积是硬约束（CLMA 91%/APM 37% 已是极限），而多趟只花带宽 —— Y1 总设里"更宽的层靠多趟复用"本来就写着。
**累加载体：采用「片上部分和缓冲」**（`C_out` 行 × 8 通道；面积小涨、无额外 DDR）。
⚠ **可回收条件**：R1 要求 **G2/G3 先量化总流量**；若量化结果说明片上部分和装不下或帧时超档，则回退到 **DDR 读-改-写**（零面积、流量↑）—— 这是**已定的退路**，不需要再裁决。

### 4.2 权重指针怎么给（C3 的 **O1**：8 个字已用满）→ **已定 (a) 表序隐含**
| 方案 | 内容 | 后果 |
|---|---|---|
| **(a) 表序隐含**（**推荐**） | 权重 blob 按**表序**连续排布，调度器维护 `wgt_ptr`（每单元权重数由几何导出：`C_out*(C_in/GROUP)*9`，**段补齐到 32 B 倍**）；描述符格式**零改动** | 隐式契约"表与权重同序"（转换器保证）；加一条"权重 blob 指纹"判据对冲 |
| (b) 加第 9 个字（`WGT_ADDR`） | 描述符 32 B → 36 B | 改冻结格式 + `DescFetch`（现取 32 B）+ `desc_table` + C3 的 6 条校验 ⇒ **动到已验收的冻结件** |
| (c) 复用 `w3` 高 16 位当权重偏移（相对表基址） | 零长度变更 | 语义挤位，可读性差，仍要改冻结格式说明 |

**已定 (a)**（用户裁决；零格式改动，与"权重整网常驻"的 Y1 冻结前提一致）。配套：**"表与权重同序"写进转换器契约**，并用 G6 的 blob 指纹 + G2 的逐层对账双保险对冲隐式契约的风险（R4）。

**★ 布局修订（2026-10-12，B0）—— 每单元段补齐到 32 B 且 32 B 对齐**

- **为什么改**（`y1/reports/c4b_wgtdma.md` §9.3 的实测阻塞）：B1/B1b 已建 DDR→权重装载路径，但主口 `DdrMaster`
  的 RD 契约是 **`src % 32 == 0` 且 `len % 32 == 0`**（C3.3 冻结）。**原（紧凑）布局**逐单元 `N_i` 首尾相接 ⇒
  真实 blob 里 `Conv_0` 段长 **432 B**（`%32 != 0`）、且被 144/288/9/36/90 等非 32 倍数段一推，**多数单元起点
  `offset ≡ 16 (mod 32)`** ⇒ 装载闸门**响亮 err**（48/53 个单元在旧布局下 `offset % 32 != 0`）。
- **已定（用户裁决 = 选项② 的"改 blob"那条，而非放宽主口）**：**转换器把每个单元的段补齐到 32 B 的整数倍**
  （`N_i' = ceil32(N_i)`），**起点 = `Σ_{j<i} N_j'`**，**补位字节 = `0`**。
- **口径（逐字）**：`N_i = C_out*(C_in/GROUP)*9`（不变的**真实**权重字节数，仅 1×1 核的其余抽头补 0）；
  `N_i' = ceil32(N_i)`（**物理**段长）；段起点 `= Σ_{j<i} N_j'`；段内 `[0, N_i)` 是真实权重、`[N_i, N_i')` 全 0。
  表序隐含（(a)）**不变**：单元仍按**表序**排列，转换器保证序与偏移。
- **对外表征**：`wgt_index.json` 的**每单元**保留 `nbytes = N_i`（**真实**，供 G2 逐字节对账）**并新增**
  `aligned_bytes = N_i'`（**物理**，供 G6 装载）；`offset` = 对齐后的起点。blob 总长 = `Σ N_i'`。
- **零格式/零契约变更**：描述符 8 字、寄存器、`DdrMaster` 契约**一字未改**；只是 blob 的**物理布局**变了。
  真表 53 个单位：真实 `Σ N_i = 403,776 B`，对齐后 `Σ N_i' = 404,064 B`（**补位开销 288 B**），且
  **全部 53 个 `offset % 32 == 0`**。

### 4.4 **requant 乘子怎么进硬件**（2026-10-10 新增裁决）→ **乘子表随权重同序散装，走既有权重信箱**

- **为什么新增**（C4a.2 实测发现，`y1/reports/c4a_quant.md` §11.3）：真实 per-tensor 量化的 requant 乘子是
  `ratio = s_x·s_w/s_y`（**任意实数**，层 0 实测 ≈ `2^-9`），而 C3 冻结的 requant 是**纯移位 `>>SHIFT(=6)`**
  （粒度 `2^-6`）。**纯移位表达不了 ratio** ⇒ 实测偏差 ≈100% 且**中间层塌成常数**（distinct=1），
  会把 G3/G4 的逐字节对账变成橡皮章。
- **已定（用户裁决）**：requant = `((acc · M) >> REQUANT_Q) >> SHIFT`，`REQUANT_Q=24`，`M` 为**每层 Q24 定点乘子**（纯整数、无层间浮点 DQ；`>>SHIFT` 仍是冻结那一步，`require_shift` 每层断言）。**M 的投递**：按**表序**排在权重 blob 之后，用**既有的 `WGT_ADDR/WGT_DATA/WGT_WE` 权重信箱**装载，用 `w7` 已带的 `LAYER_ID` 索引 ⇒ **描述符 8 字格式零改动**（守住 §4.2 的"零格式改动"）。
- **对 C4a.3/C4a.5 的接口约束**：① 转换器要在 `wgt_index.json` 里给出每层 `M`（新增一段 `requant_mult` 表）；
  ② C4a.5 的 RTL 在 requant 处加 **乘 + 双移位**（`Conv3x3Slice` 现只有 `>>6`）⇒ 面积小涨，**必须重跑 PnR**
  （C3 的 CLMA ~91% 已满，见 R3）。③ `w7` 的 `LAYER_ID` 从"C3 的可选标签"升为**乘子索引**（语义加重，格式不变）。

### 4.5 **zero-point 中心化怎么落**（2026-10-10 裁决，2026-10-11 修正）→ **权重改对称量化（`z_w≡0`）+ 零填充用真 0 码点 `z_x` + 偏置预调；MAC 仍 int8×int8**

- **为什么新增**（C4a.5 实测发现）：C3 的 `Conv3x3Slice` 只算 `Σ x·w`（`mac_ref` 口径），**没有** x/w 的
  zero-point 中心化口；而 C4a.2 的黄金算的是 `Σ (x_q−z_x)(w_q−z_w)`（affine 口径），真网的 `z_x`（ReLU 输出 lo=0
  ⇒ `z_x=−128`）与 `z_w`（权重非对称 ⇒ ≠0）**都不为 0** ⇒ 硬件与黄金**对不上**。
- **★ 修正（2026-10-11）**：最初拟"存中心化权重 `c_q = w_q−z_w` 且 MAC 仍 int8"——**该推导有误**：实测
  `c_q` 的真值域是 `[−255,255]`（**50/53** 个权重单元需 **9 bit**），因为权重区间不含 0 时 `z_w` 落在码轨上、
  `c_q` 不再居中。原 200 组探针只证了**代数恒等**（用 int64 算 `c`），**没证 int8 可表示**。
- **已定（用户裁决 = A）**：**权重改用对称量化**（`z_w ≡ 0`，`scale = max|w|/127`）⇒ `w_q ∈ [−127,127]` **恰落 int8**，
  MAC **零位宽改动**（面积是硬约束：C3 CLMA ~91% 已满）。代价：少数非对称权重张量（全正/全负的 1×1 与 bias）
  损失 ≈1 bit 量程；且**要重标定权重 ⇒ 重跑 C4a.2/3/4/5a 的黄金与门卡**（机械重跑）。代数（与 §4.4 的 `M` 配套）：
  ```
  z_w ≡ 0                  # 权重对称量化；w_q ∈ [−127,127]
  零填充 = 真 0 的码点 z_x  # 不是字节 0！golden 就是这么补的；pad 值随层变
  bias' = round(bias/(s_x·s_w)) − z_x · Σ_all-taps w_q     # 每输出通道一个常数
  acc  = Σ x_q · w_q + bias'  ≡  Σ (x_q − z_x)(w_q − 0) + bias/(s_x·s_w)   # 恒等（pad 用 z_x 的边界抵销已证）
  ```
- **对 C4a.1/C4a.3/C4a.5 的接口约束**：① `quant_ptq` 加**权重对称量化**（`z_w≡0`），golden 与转换器**同口径复用**；
  ② 转换器每层导出 **`z_x`（pad 值）** 与 **`bias'`**（权重 blob 仍是 `w_q`，**布局不变**）；③ **RTL 的唯一新增**：pad 行/列的值 = `z_x`
  （现在硬编码 0）；`z_x` / `bias'` / `M` 经**既有权重信箱**按 `LAYER_ID` 投递 ⇒ **描述符 8 字仍零改动**；④ **MAC 位宽不变**（int8×int8）。

### 4.6 ★ 修订（2026-10-13，E1）—— `Add` 第二路输入用**保留位「表内偏移」约定**（**8 字格式不变**）

- **背景**：`Add` 是本代四类旁路算子里**唯一的双输入**单元（`AddUnit` 的 `x_a`/`x_b`，见
  `rtl/AddUnit.scala` 文件头 §O1）。冻结的描述符格式（§3，C3.2）**只有一个 `SRC_ADDR`**
  （`reports/c3_descriptor_format.md` §7 开口项 O1）。真网的两个 `Add`（`Add_44`/`Add_50`）两路**都来自
  DDR**、且来自**两个不同的生产者**（`Resize_43`/`Resize_49` 的输出 + 一个 conv 尾（`Relu` 折进）的输出）
  ⇒ 格式**表达不了第二路源**。本修订把 O1 收口。
- **裁决（用户 2026-10-13）**：**不加字段、不改 8 字格式**；用**当前保留/未校验**的位编「第二路源 =
  表内偏移 `k`」。**选位 = `w3[31:16]`**（`GROUP/STRIDE/PAD` 之上那 16 位保留段）。
  - **为什么是 `w3[31:16]` 而不是 `FLAGS` 的保留位 `bits[7:2]`**：`FLAGS[7:2]` 被冻结的
    `desc_table.validate` 规则 (2)（`FLAGS_RESERVED_MASK=0xFC`）在**读侧**强制为 0，且被 RTL
    `LayerSched` 的 `flagsReserved` 响亮拦住 —— 碰它要动两处**冻结校验**（正是本任务禁止的）。
    而 `w3[31:16]` **不在**任何冻结校验里：`pack` 恒写 0、`validate` 六规则**不看**它、RTL 也**不查**它
    ⇒ 是**真正闲置**的保留位。代价：`pack` 不搬运它（不是 14 字段之一）⇒ 由**转换器在 `pack_table`
    之后按字偏移 OR 进去**（`w3` 的高 16 位）；`unpack`/14 字段往返**不受影响**。
- **语义（冻结，逐字）**：
  - `SRC2_K = w3[31:16]`，**无符号 16 位**小整数；
  - `SRC2_K == 0` ⇒ **"没有第二路源"**（缺省；**所有非 Add 项恒为 0**）；
  - `SRC2_K == k > 0` ⇒ 仅对 `Add` 有意义：**`Add` 的第二路源 = 表序下行 `k` 位那条描述符的 `DST_ADDR`**
    （即 `SRC2_ADDR = DST_ADDR[ idx - k ]`，`idx` = 本 `Add` 的表序）；
  - **非 Add 项 `SRC2_K != 0` ⇒ 表非法**（响亮 `err`；RTL 在分派前拦，Python 侧记在 `wgt_index.json`）。
  - **`Add` 的 `SRC2_K == 0`**：保留 C3.7 的**列交织**旧约定（第二路 = 同一 `SRC_ADDR` RD 流里
    `+C` 字节那个偏移）—— 这是**已定义的兼容行为**（不是错误）；真网两个 `Add` **都**用 `SRC2_K = 1`
    （表内偏移路径），故走本修订的新通路。
  - `k` 的上界 = RTL 的**表内 DST 历史深度** `D`（见下）；`k > D` 或 `idx - k < 0` ⇒ 响亮 `err`。
- **RTL 落实（`LayerSched` 复用**已有的走表**，不加第二趟取表）**：`LayerSched` 在走表时把每条被取到的
  条目的 `DST_ADDR` 存进一个**深度 `D` 的环形历史**（按条目下标 `mod D`），分派 `Add` 时取
  `history[(idx - k) mod D]` 作为 `BypassExec.io.src2`。`BypassExec` 据 `w3[31:16] != 0` 走**两趟读**
  （先读 A 存片上、再读 `src2` 的 B 并与 A 逐列饱和相加），不再依赖列交织。
- **与本修订**无关的冻结物**不动**：`desc_table.py`（冻结位打包/六规则）、描述符**字数（8）**、
  `SRC_ADDR` 字段语义、`AddUnit` 的算术（饱和加）。
- **口径说明（诚实记录）**：真网的 \(k=1\)（两个生产者在 `Add` 的前一条）；且都在**无链的普通项**处
  ⇒ "表内偏移"在本网等于"上一条被分派的单元"。更深/更远的 `k` 由 `D` 覆盖（本代取 `D=8`）。

### 4.3 量化口径（2026-10-10 新增裁决）→ **自研 affine PTQ + 同口径 Python 参考**

- **为什么新增**：`yunet.onnx` 是 **float32、无 QDQ**（实测）⇒ 转换器不能只"抽取量化参数"，**它必须自己做 PTQ**（此前的 spec 有这个缺口；也解释了 C3 里 Sigmoid 的 Q3.4→Q0.7 只能是占位值）。
- **已定**：**自研 affine PTQ**（per-tensor `scale`/`zero-point`，校准用 min/max 或 percentile），**同口径 Python 参考**作为硬件判据的基准。
- **口径修订（2026-10-10 r2，C4a.1 执行中发现）**：求 `scale/zp` 前**先零值纳入**（`lo=min(lo,0)`、`hi=max(hi,0)`）。
  理由：per-tensor affine 必须能**精确表示 0**；否则区间不含 0 的张量 `zp` 越界被 `clamp` ⇒ 整张量塌成几个码点。
  实测 `yunet.onnx` 有 **22** 个张量区间不含 0，其中 **10** 个（含 **3 个真 conv 权重**）在旧口径下退化到 `err>scale/2`，
  最坏丢 **89.7%** 量程 ⇒ 若不修，转换器会静默烤出塌缩的权重 blob。**affine 公式一字未改**（只改喂给公式的区间）；
  另修 `--percentile` 取分位序（`sorted([p,100-p])`）。判据/证据见 `y1/reports/c4a_quant.md` §2/§4/§6/§10.3。
- **G2 的口径随之修正**：逐字节对账的基准是**同口径参考**（不是 float ORT）；与 **float ORT** 之间只做**容差级**比较。
- **G7 的容差（本 spec 拟定，可调；用户未给数）**：匹配框 **IoU ≥ 0.5**、关键点**平均 L2 ≤ 2 px**（640×640 输入尺度）、置信度 **|Δ| ≤ 0.1**、**检出数差 ≤ 1**。
- ⚠ 不做 QAT/微调（Y1 总设明确）⇒ PTQ 掉精度的风险由 G7 的容差守住；**若 G7 达不到，先查校准口径（percentile/每层 vs 全局），再谈是否放宽容差**。

## 5. 判据（C4-G1 … G7；每条都要**正负对照**）

- **G1（C4.0 闸门）**：真模型资产三件套（算子序列 / 权重 / 量化参数）导出并记指纹；**三态覆盖面表**（覆盖/需主机旁路/不覆盖）与 C3 冻结表逐项对账。
- **G2（转换器 + PTQ）**：生成的表过 `desc_table.validate` + `pack/unpack` 往返；**权重 blob 装进 `WeightStore` 后与"同口径（自研 PTQ）的 Python 参考"逐层逐字节对账**（基准是**同口径参考**，不是 float ORT）；与 **float ORT** 只做**容差级**逐层比较（记录最大偏差）。负对照：改 1 个权重 / 改 1 个 scale ⇒ 必红。
- **G3（通道覆盖）**：真表**每种 `(C_in,C_out,GROUP)` 形状**各跑一层，逐字节对参考；多趟累加的**进位/饱和口径**要有专门负对照（漏加一趟 ⇒ 必红）；**每层拍数与预测对上**（吞吐不许悄悄退化）。
- **G4（depthwise）**：真表 20 个 depthwise 层逐层对账；负对照：group 映射错 ⇒ 红。
- **G5（布局算子）**：`Transpose/Reshape` 折进寻址后，输出与"显式转置"参考逐字节一致，且 **DDR 读+写字节数不增**（证明没有额外搬运）。
- **G6（权重从 DDR）**：blob 批量装载后 `WeightStore` 与 blob **逐字节相等**；装载字节数 == blob 大小；装载与计算的**重叠纪律**写明并实测。
- **G7（端到端 + 帧）**：同一张图，硬件（+ CPU 后处理）结果 vs **float ORT（+官方后处理）**在**容差**内一致：**匹配框 IoU ≥ 0.5、关键点平均 L2 ≤ 2 px（640×640 尺度）、置信度 |Δ| ≤ 0.1、检出数差 ≤ 1**（本 spec 拟定，可调）；**负对照**：喂无人脸的图 ⇒ **无检测**；给出**整帧 DDR 流量与帧时**（并声明是下界/上界口径）。
- **全程**：每轮 RTL 改动后重跑 **15 个单元闸门 + 台账 + PnR**（`All Constraints Met` 且面积不越预算）。

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| R1 | 多趟累加把 DDR 流量推高 ⇒ 帧率跌破档位 | **G2/G3 先量化总流量**再决定 (b) 的实现（片上部分和 vs DDR 读改写）；与 C5 的真实带宽合账 |
| R2 | 量化参数（每层 scale/shift、Sigmoid 真刻度）与 ORT 不一致 | G2 的逐层对账就是它的判据；Sigmoid 的定点口径要在 G1 里从"占位"升级为**真值** |
| R3 | 面积：CLMA 已 ~91% 满 | 任何切口/缓冲都走 S5 的 `dev_map`；超预算则回退（多趟的片上部分和是可裁剪项） |
| R4 | 权重"表序隐含"契约被破坏（转换器与调度器不同步） | G6 的 blob 指纹 + G2 的逐层对账双保险 |
| R5 | 上板通道脆弱（UART 长循环 / 回显陷阱） | 沿用 `c3_board_bringup.md` §5.1 的三条口径；大 blob 优先走**网络（dropbear 已起）** |

## 7. 明确不做（C4 边界）

- 不做帧率/CPU 争用实测（C5）；不做摄像头/前处理硬件（Y5 的摄像头接管）；
- 不做训练/量化感知训练；不改 C3 的调度语义与描述符**语义**（§4.2 若选 (a) 则**格式一字不改**）；
- 不做后处理硬件（decode/NMS 留 CPU）。

## 8. 依赖

- **板上通路的两个前置**：① 大 blob 用 UART 太慢 ⇒ 建议启用**网络通道**（主板网口/网段要确认）；② 真权重/真图的来源（ONNX 已在仓内、指纹已记）。
- **C5**（帧率/争用）在 C4 之后；**C5 的输入**就是 C4-G7 的流量与帧时。
