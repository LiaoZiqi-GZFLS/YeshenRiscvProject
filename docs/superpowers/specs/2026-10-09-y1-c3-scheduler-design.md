## 1. 目标与范围

**C3 是什么**：把已建成的「DDR 主口 + 主机寄存器层」扩成**层调度器** —— 主机在 DDR 里写一张**描述符表**（整帧的算子序列，含融合单元与旁路算子），发**一条命令**，NPU 自己走表把整帧跑完，做完给一次中断。

**C3 不是什么**：不是转换器（模型 → 表由 C4/M2 生成）、不是前/后处理、不是帧率验收（C5）、不碰摄像头（Y5）。

## 2. 冻结参数

| 项 | 冻结值 | 依据 |
|---|---|---|
| 编程模型 | **DDR 描述符表**：主机写表一次 + 发一条命令，NPU 自己走表 | 用户拍板（逐单元寄存器会让 15fps 下 ~500 次中断/秒） |
| 调度粒度 | **按融合单元，行流式** | C3.0：整块驻留**双缓冲装不下**（2×356 = 712 > 390.5 DRM） |
| 融合缓冲 | **30,720 B = 7 个 DRM36K**（3 行 × 最坏 `C·W=10,240`） | C3.0；余量 +98.2% |
| 缓冲载体 | **必须是 RAM 结构（`GTP_DRM36K`），不得落 FF** | C3.0：30,720 B 按 FF 是 245,760 > 空闲 215,004；且 **PDS 忽略 `ram_style`** ⇒ 只能靠**结构**逼 |
| 主时钟 / 总线 | `soc_clk` 100 MHz；内存口 `AXIIO64`（64bit / 4bit id） | 既有 |
| 既有寄存器 | `HostRegs` 13 格（`f000c000`，PLIC 源 3）**扩展**：加 `DESC_ADDR` / `DESC_COUNT` | C1/C2.2 |
| 长度口径 | **每单元在表里显式给读写字节数**；**不再**用 `len = IMG_W×IMG_H×C_IN` | 该推导对流式融合单元**不成立**（C3.0 指出） |
| 旁路算子 | **进硬件**：`MaxPool`(4) / `Resize`(2) / `Add`(2) / `Sigmoid`(6)。**`Transpose`(12) / `Reshape`(12) 不进硬件** —— 它们是**布局**算子，由 C4/M2 的**转换器折进寻址**（不占数据通路，符合"结构性优先"） | 用户拍板「直接加硬件」；这样**一帧只有一次中断**，正是描述符表被选中的理由 |

## 3. 描述符格式（冻结语义；位打包留到计划）

每项 **8 个 32-bit 字**，字段语义：

| 字 | 字段 | 说明 |
|---|---|---|
| w0 | `TYPE`[7:0] \| `FLAGS`[15:8] | TYPE：`0x01` conv3x3 / `0x02` conv1x1 / `0x03` depthwise / `0x10` maxpool / `0x11` resize / `0x12` concat / `0x13` add / `0x14` sigmoid / **`0xFF` 表尾哨兵**。FLAGS：**bit0=输出落 DDR**（=0 表示留给下一单元用，即融合单元的**头**）；**bit1=输入取「上一单元输出」**（=1 表示不读 DDR，即融合单元的**尾**）。融合单元就由这两位的组合表达，不需要额外的"融合标志" |
| w1 | `IMG_W`[15:0] \| `IMG_H`[15:0] | 该单元的（输出）特征图几何 |
| w2 | `C_IN`[15:0] \| `C_OUT`[15:0] | 通道 |
| w3 | `GROUP`[7:0] \| `STRIDE`[3:0] \| `PAD`[3:0] | 分组与 3×3 的步长/填充 |
| w4 | `SRC_ADDR`[31:0] | 显式源地址（当 FLAGS.bit1=1 时被「上一单元输出」覆盖） |
| w5 | `DST_ADDR`[31:0] | 显式目的地址 |
| w6 | `IN_BYTES`[31:0] | 该单元要读/写的**激活字节数**（显式；流式单元也成立） |
| w7 | `QUANT_SHIFT`[7:0] \| `LAYER_ID`[15:8] | 量化与遥测身份 |

**执行序 = 表序**。表由 C4/M2 的转换器生成（C3 只消费）。`DESC_COUNT` 与哨兵必须自洽（否则报 `err`）。

## 4. 关键落点

**复用（不改语义）**
- `y1/rtl/HostRegs.scala` —— 扩展出 `DESC_ADDR`/`DESC_COUNT`（沿用 `Cat` 表达式风格；勿用多语句赋值构造只读字，会生成敏感列表不翻转的 `always @(*)` 并在 iverilog 里停在 X）；
- `y1/rtl/DdrMaster.scala` —— 复用它的块拷贝做**描述符表的读取**与**特征搬运**（同一条 AXI 主口，仍守 P1–P6）；
- `y1/rtl/{MacArray, GroupMask, GroupedMacArray, WeightStore, Conv3x3Slice, LineBuffer}.scala` —— 阵列/权重/窗口。

**新增**
- 描述符解析器（取表 → 逐项译码 → 拉控制）；
- **行流式融合缓冲**（RAM 结构，参数化 `(C, WIDTH)`，深度 3 行；见 §5 S5 判据）；
- 单元序列状态机（按表推进 + 旁路算子的编排点）。

**只读参考**：`y1/tools/ddr_traffic.py`（融合枚举——表的内容由它决定）、`src/soc/DDR3Bridge.scala`（桥的纪律）。

## 5. 验收判据

**S1 描述符表往返**：主机写表 → NPU 读回并**逐项回显**到遥测寄存器/内存。判据：与主机写的**逐字节一致**；负对照=表里一项被改一个字节，必须抓到。

**S2 单单元（不融合）**：走表跑一个 3×3 dense conv，与 Python 参考对账。判据：`MISMATCH=0`（沿用既有判据的"非平凡向量 + 三区比对"风格）。

**S3 融合单元（本档的核心）**：跑一个 `1×1→3×3` 融合对。判据有**两条**：
- 结果与"分两步、中间张量落 DDR"的参考**一致**；
- **中间张量真的没落 DDR**：DDR **读+写字节计数**等于预期（少掉的正好是中间张量那 `2×size`），并断言该中间张量的地址区间**未被写过**。

**S4 多单元序列（含旁路算子，且**帧内零中断**）**：跑 ≥3 个单元，**其中至少包含一个旁路算子**（MaxPool / Resize / Add / Sigmoid 之一），与 Python 参考一致。判据另有两条：
- **帧内中断计数 == 0**（只有帧末那一次完成中断）—— 这是"旁路算子在硬件里"的可观测证据；若出现帧内中断说明表把某个算子标成了"主机代做"；
- 旁路算子的**输出必须与参考逐点一致**（不能只验"跑完没报错"）。

**S5 面积闸门（含"真的落 DRM"的判据）**：含融合缓冲的 `dev_map`。判据：
- **DRM 用量 ≥ 7 块**且 SoC + 本档 ≤ 415；
- 且**断言缓冲真的在 DRM 里、不在 FF 里** —— 按 M0 的教训看三样：`DRM` 用量、`Adm-4088`（DRM 不够转 LUTRAM）条数、`LUTs as dram`；
- ⚠ 因为 **PDS 忽略 `ram_style`**，若实测落到了 FF/LUTRAM，**改结构**（尺寸/端口形态）而不是加属性。

**S6 非法表**：越界地址 / 自环 / 非法 TYPE / `DESC_COUNT` 与哨兵不符 ⇒ **响亮 `err`**（状态位 + 中断），**零搬运**。负对照=合法表必须不报 err。

## 6. 风险与开放问题

| # | 风险 / 开放项 | 说明与处置 |
|---|---|---|
| **R1（已裁决）** | 旁路算子走**硬件**：`MaxPool`(4) / `Resize`(2) / `Add`(2) / `Sigmoid`(6)；`Transpose`(12) / `Reshape`(12) 由**转换器折进寻址**（不进硬件）。⇒ 一帧一次中断 | 用户拍板。**残留风险**：这四条新数据通路 + 描述符解析器的**面积未估**（R2），必须由 **S5 的 `dev_map`** 量出来；若超预算，退回"给最重的两个加硬件、其余由主机在帧末做" |
| R2 | 描述符解析器 + 四条旁路通路的面积/复杂度未估 | **S5 面积闸门**就是它的判据；若过大则按 R1 的退路裁剪 |
| R3 | 表格式必须与 C4/M2 的转换器对齐 | 现在冻结**语义**、位打包留到计划；转换器落地时若需改，走 spec 修订 |
| R4 | 每帧启动延迟 + 表自身的 DMA 读开销 | 表很小（33 项 × 32 B ≈ 1 KB），预计可忽略；S4 里量一次 |
| R5 | 融合缓冲与权重存储对 DRAM 端口的争用 | 权重常驻、融合缓冲在片上；仍需在 S5 的 `dev_map` 后核对端口组织 |
| R6 | **C0 的流量模型是下界**：只计 Conv 的输入/输出，**不含旁路算子自身的激活读写**、不含 12 个头张量的后处理 | 真实流量更高 ⇒ 12.58 MB/帧 的 21.94 fps 会打折。C5 用真实负载实测；C3 至少要**把旁路算子的流量补进模型**（一条便宜的离线补充） |
| R7 | CPU 争用下的桥份额 | 属 **C5**（带负载实测），C3 不解决 |

## 7. 明确不做（C3 边界）

- 不做转换器（模型 → 表）—— C4/M2。
- 不做前处理（letterbox / RGB565→888）与后处理（decode / NMS）—— C4。
- 不做帧率验收、不做 CPU 争用实测 —— C5。
- 不动 `src/soc/DDR3Bridge.scala`、不动 DSP/DRC 的纪律（它们是输入约束）。
- 不上板。

## 8. 已裁决（2026-10-09）

**旁路算子 = 直接加硬件。** 落到冻结范围（见 §2）：`MaxPool` / `Resize` / `Add` / `Sigmoid` **进硬件**；`Transpose` / `Reshape` 由**转换器折进寻址**（布局算子不占数据通路）。

⇒ **一帧只有一次（帧末）中断** —— S4 据此判「帧内中断计数 == 0」。

**残留**：这四条新数据通路（+ 描述符解析器）的**面积未估**，由 **S5 的 `dev_map`** 量出来；若超预算，退路是「只给最重的两个加硬件、其余由主机在帧末一次做掉」（即 §6 R1 的退路）。
