# GPU P2a 3D 光栅器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已完成的 2D GPU 上增加屏幕空间 3D 渲染（CPU 顶点变换 + flat 着色 + Z 测试 + 32×32 tile 分桶），并提供可互动的 3D 窗口应用（触摸拖拽 yaw/pitch、按钮缩放）。

**Architecture:** 新增 `rtl/gpu/gpu_3d.v`，挂在 `gpu_top` 里与 `gpu_2d` 并列，共用 `gpu_mem` 读写引擎（同一时刻只有一类在飞，沿用现有串行契约）。命令 op 沿用 `gpu_regs.vh` 预留的 `0x10/0x11/0x12`（CLEAR3D / DRAW_TRIS / COMPOSITE3D），DDR 布局沿用已定义的 `GPU_COLOR3D 0x9300_0000` / `GPU_Z3D 0x9310_0000` / `GPU_ARENA 0x9320_0000`。

**Tech Stack:** Verilog-2001 RTL + Verilator 单元/子系统闸门 + PDS（dev_map / PnR）+ RV32 Linux 用户态。

**依据：** `docs/superpowers/specs/2026-10-30-simple-gpu-design.md` §6（3D 引擎）、§7（显示）、§11（分批）、§12（资源预算）。

## 范围与验收（P2a）

| 项 | 判据 |
|---|---|
| 光栅正确性 | C 黄金逐像素（颜色 + Z）比对，128×96 与 640×480 两档 |
| Z 语义 | `LESS`（默认）/`LEQUAL`（`DRAW_TRIS.flags[0]`）；负对照：关 Z 时后画覆盖前画 |
| tile 分桶 | 300 tile 全覆盖：分桶后与"不分桶"逐像素相同；溢出 tile 走即时 RMW 回退且结果相同 |
| 复合 | `COMPOSITE3D` 把 COLOR3D 的 640×480 拷进 GUI bank 指定矩形，逐字节 |
| 性能 | 640×480 场景 ≥ 15 fps（CPU 顶点 + GPU 光栅，整帧 wall clock） |
| 面积 | 相对 gpu10：LUT ≤ +8 K、DRM ≤ +6、APM ≤ +4（dev_map 实测记账） |

## M1 光栅数学（单元级，先红后绿）

### Task 1: 黄金 + 先红的闸门骨架

**Files:**
- Create: `sim/gpu/tri_ref.py`
- Create: `sim/gpu/run_tri_ab.sh`

- [ ] **Step 1: 写 Python 黄金**（`tri_ref.py`，**已完成**：`--selftest` 六条性质 PASS）

> **与 spec §6.2 的偏差（已定案）**：spec 写"顶点 8 B `{int16 x_q8_8, int16 y_q8_8, u16 z, u16 pad}`"，
> 但 int16 的 8.8 只覆盖 ±128 px，装不下 640×480 屏幕。改为 **16 B `{s32 x_q8_8, s32 y_q8_8, u16 z, u16 pad, u32 pad2}`**
> （128 三角形×3 顶点 = 6 KB/帧，带宽可忽略；32 B 一拍正好 2 个顶点，读侧对齐简单）。
> 边函数与 Z 平面的整数口径写在 `sim/gpu/tri_ref.py` 头注释里，RTL 必须逐条照抄。

- [ ] **Step 1 说明**：输入顶点列表 + 宽高 + Z 模式，输出每像素 `{color, z}`。
  约定：顶点 `{x_q8_8, y_q8_8, z}`；边函数 `E(x,y)=A*x+B*y+C`，`A=y0-y1`、`B=x1-x0`、`C=x0*y1-x1*y0`（定点同 RTL）；
  像素中心采样 `(px+0.5, py+0.5)`；`E>=0` 为内部（含边界，顺时针为正）；Z 用 `z = z0 + dzdx*px + dzdy*py` 的整数增量式。
- [ ] **Step 2: 写闸门**：生成 6 个三角形用例（小/大/退化/共边/越界/背面），跑 RTL 与黄金逐像素比。
- [ ] **Step 3: 先跑红**（RTL 不存在 ⇒ 构建失败，记录为红证据）。

- Create: `rtl/gpu/tri_setup.v`

## 风险与回退

1. **setup 乘法吞吐**：每三角形 ~30 次 24-bit MAC 串行 ⇒ 128 三角形 ~3.8 K 拍 ≈ 38 µs @100 MHz；若成为瓶颈，改 2 个 MAC 并行（+1 APM）。
2. **tile 读改写带宽**：2.4 MB/帧；现有 DDR 有效带宽 ~275 MB/s，余量足够；若不够，先降到 32×64 tile（150 tile）。
3. **Z 缓冲初值**：`CLEAR3D` 必须每帧清 Z（0xFFFF）；忘记清会导致"不画"的假象——闸门里专门有一条用例。
4. **交互延迟**：CPU 单核 100 MHz；MVP 128 三角形 ≈ 6 K MAC + 384 div ⇒ 0.4–0.7 ms，可接受。

## 与 P1 的关系

P2a **不改** 2D 链路：`gpu_2d.v` 与 `gpu_mem` 的 32 B 对齐契约保持不动；新增引擎只增加 op 分发与一条 `u_3d` 实例。
P1 的所有闸门（`run_2d` / `run_2d_trunc32` / `run_mem` / `run_csr` / `GPU-GLUE`）在 P2a 每个里程碑后必须原样全绿。
