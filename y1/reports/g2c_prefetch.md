# G2-c 实现记录：band 预取（双 bank，按地址 bit5 分体）

日期：2026-10-24　状态：**RTL 落地 + 归一化冻结证据已过；单元闸门与 A/B 在跑**

## 1. 与 spec 的差异（先说清楚）

`g2c_op_owner_spec.md` 的 Step A 用 **`wxGAbs(5)` 作为 bank 位**，这在"同一列的 8 个平面 band 地址
bit5 可能不同"时是错的（平面步进 `tInPixW` 不必是 64 的倍数；c64_40 的 `34×34=1156`，1156 mod 64 = 4）。
本次实现改成 **每个平面自己的 band 地址 bit5**（读 = `wxPBB(cl)(5)`、写 = 该项 band 地址的 bit5），
两端口自动一致，**不需要任何 bank 状态寄存器**。

由此 Step A+B 合并成一处改动（无需先合 Step A 再改）：

| 件 | 位置 | 做法 |
|---|---|---|
| 双 bank | `xwBuf` | TILING 下 32 → **64** 项；非 TILING 仍 32（冻结） |
| 读口 | `wxWord` | `Cat(wxPBB(cl)(5), cl*4 + wxPIDX(cl)[4:3])` |
| 落数口 | 主批 / 预取批 | `Cat(itemBandAddr(5), plane*4 + beat)` |
| 预取账本 | `wxPfV(p)/wxPfB(p)` | "另一 bank 里装着平面 p 的某条 band"（地址精确比对） |
| 命中判据 | `wxPNE` | 在既有 `!(wxBndV && PBB==wxBndB)` 之外再 `&& !(wxPfV && PBB==wxPfB)` |
| 命中处理 | DECIDE | 只改账本 `wxBndB := wxPBB`（bank 由地址决定，自动换体），并挂下一条预取 |
| 预取请求 | 落数 done / 命中 | `pfTgt(p) := band + 32`；**仅当 `wCol+32 < tNCol`**（本行还够 32 列）才挂 |
| 预取引擎 | `pfSt` | IDLE → SCAN（逐平面入队，`sg_ready` 反压）→ RD（收流落另一 bank）→ done 置 `wxPfV` |
| 主口互斥 | DECIDE / sg_* | 引擎只在 `wxSt != FETCH && !busy` 起；主批 DECIDE 见 busy 走既有排空/重扫 |
| 排空死等兜底 | FETCH·Drn | 若 `busy` 在 DECIDE 后一拍就落（预取批正好收完）⇒ **`!busy` 直接跳过等待**（否则挂死） |
| 收工门 | 趟末 | 最后一个像素出后**等主口 idle**（`wxFinR && !busy`）才进 WR 相位 —— 否则 WRRUN 的
`start(mode=2)` 会撞在飞批上（DdrMaster 的 `start` 只认 IDLE） |

收益模型：每换一次 band 的代价 = 一次 RTT；预取把这次 RTT 藏在同 row 后续 ≤32 列的喂列后面。
**行首仍是冷的**（每行至少一次真 RTT），跨行预取留给后续 K 环。

## 5. 时序结论（2026-10-24）：**60 MHz 下不收敛，G2-c 暂不进交付**

`npu60c`（60 MHz 约束 16.667 ns + G2-c）PnR seed 0：

| 域 | 60 MHz 基线 `npu60b` | `npu60c`（+G2-c） |
|---|---|---|
| `npu_clk` | 60.6024 MHz / **+0.166** | 53.6855 MHz / **−1.960** |
| `soc_clk` | +0.760 | −0.440 |
| `cpu_clk` | +0.249 | −0.351 |
| `core_clk` | +0.649 | −0.287 |

`Design Summary: Some Constraints Violated`；多 seed 表 seed0 `UserFilter=0`、
`Worst Slack(place) −2661`（基线是 −645）⇒ 不是单点抖动，**放置/布线质量整体变差**。

头号路径（seed0）：`tTw` 减法 → `≥` 比较 → APM 乘法 → 减法 → APM 乘法 → **32 位相等** → APM.CE，
17 级 / 逻辑 9.257 ns / 布线 8.591 ns（布线占 48%）。它走的是 `wxPBB`（`srcA + ci·HW + IY·行宽 + G`）那条链。

**两条候选解释（未做对照实验，别当定论）**：
1. `wxPNE` 上多了一个 32 位比较（`PBB === wxPfB`）⇒ 判断链变长；
2. `xwBuf` 32→64 项让 8 个 lane 的读口从 32:1 变 64:1 ⇒ 走线/拥塞吃掉 placement 质量
   （LUT 只 +2,017，但布线主导路径从 7.3 ns 涨到 8.6 ns）。

**下一轮的最小改法（先做 1，再评估 2）**：
1. 把"预取命中"改成**一位 + 短比较**：预取 done 时算一次 `wxPfNx(p) := (预取 band == 当前 band + 32)`；
   DECIDE 只判 `wxPfNx(p) && (wxPIDX(p) + s > 31)`（5~6 位比较），行推进时清 `wxPfNx`
   ⇒ 头号路径上少一个 32 位比较，也少 8×32 位 `wxPfB`。
2. 若仍不收敛：把"另一 bank"改成**按 lane 分块**（每 lane 32 B 独立小存储）或把读口拆成
   "当前 band 走寄存器、预取 band 走 DRAM 端口"，把 64:1 读口降回 32:1。

**当前交付口径**：`npu60b`（60 MHz，无预取）**All Met**、比特流 `6906faf1…`；
G2-c 的 RTL/闸门/面积账留在仓库（`ddabb49`），**板级 A/B 暂不做**（没有可烧的 G2-c 比特流）。

### 5.1 试过并**回退**的一版：1 位命中标志（跨界判据）

为了让 32 位比较离开头号路径，试过：预取 done 时只存一位 `wxPfNx(p) := (预取 band == 当时 wxBndB+32)`，
DECIDE 用 `wxPIDX(p) === 31`（行内地址每列 +1 ⇒ 跨界）判定命中，行推进时清位。

- 结果：**c64_40 正对照直接红**（装置未 PASS）⇒ 该判据与真实语义不等价（只比"这一列跨界"，
  没有确认"另一 bank 里那条 band 就是要的那条"；多条预取/被打断的批会让标志与数据脱节）。
- 处理：**已回退**（`git checkout` 回到 `ddabb49` 的"整地址比较"版），并重新生成网表
  （冻结三元组回到 `08d007d8 / acf4cd59 / b896b300`，tiled `dca3d11b`）。
- 教训：命中判据是**地址级**语义（谁在哪个体），不能用"位置推断"替代；要提频得换别的口子
  （例如把 `wxPBB` 提前一拍寄存，或用"消费侧只读当前体 + 预取体只写"的双口结构）。

## 7. G2-c 的天花板：用 W3 的实测相位计数算（2026-10-24，离线）

W3 的 conv15 相位分解（`tile_wr_overlap_spec.md §W3 之后`，`PHASE3 col_ok=924800
no_valid=1246496 mpu_busy=941952`，合计 = 喂列相位 3,113,248 拍 = 4,549,064 的 68%）：

⇒ **G2-c 的上限 = −27.4%**（全藏）；报告 §3 的目标线是 `≤0.85×`（−15%），可视为"藏一半以上"的保守档。

|---|---|---|---|
| 无 G2-c（现交付） | 1,473 ms | **~1,326 ms** | 0.75 |

⇒ G2-c 是"到 1 FPS 的最后一块"，**但它的收益只有在板上量过 `npu60b` 的实测基线之后才好定价**
（模型里的 1,473 ms 本身还没上板）。顺序：先量 60 MHz 基线，再决定是否攻 60 MHz + G2-c。

### 7.1 若再攻 60 MHz + G2-c：唯一还没试过的低风险切口

`npu_clk_raise.md §8.5` 已定位头号路径穿过 `ddrMaster.io.rd_ready`，而 G2-c 往这个表达式里
加了一项 `(pfSt === RD)`（`UnitExec.scala:2672`）。

候选（**未实施，先记在这里**）：把**预取侧**的状态项换成**寄存一拍的副本**，让主 FSM 的组合路径
回到 `npu60b` 的长度（那版 +0.166 是 All Met 的）。

⚠️ 已知风险（必须先想清楚再动手）：`rd_ready` 多举/晚举一拍 = **多弹/少弹一拍数据**，
不是"只影响预取"——`rd_ready` 是 DdrMaster 的出队条件。所以这一改必须：
1. 先证"预取批的 `rd_ready` 与主批**不共用同一个出队计数**"（否则一拍偏差直接丢字节）；
2. 用 `run_b1_tilebuf_ab.sh`（conv15 + c64_40 逐字节 + `GATHER_BYTES==GEXP`）与
   `run_nputop_sched_ab.sh`（4 作业 + 负对照）双闸；任一红即回退；
3. 双时钟闸 `run_twoclock_ab.sh` 也要过（预取跨 `npu_clk` 边界）。

若 1 不成立（大概率共用），这条路就不做——**不值得拿数据正确性换 0.86 ns**。

### 7.2 交付路线 B'：**56.25 MHz + G2-c**（只改约束/PLL，不动 RTL）

用两版实测 slack 反推 G2-c 的时序代价：`npu60b` +0.166、`npu60g`（+G2-c）−0.860 @16.667 ns
⇒ **代价 1.026 ns**。于是 G2-c 能装进多高（VCO 675 MHz，`RATIO0` 以 0.25 为步进）：

| `RATIO0` | f | T (ns) | G2-c slack ≈ |
|---|---|---|---|
| 11.25 | 60.000 | 16.667 | −0.860 |
| 11.75 | 57.447 | 17.407 | −0.120 |
| **12.0** | **56.250** | **17.778** | **+0.251** ✅ |
| 12.5 | 54.000 | 18.519 | +0.992 |

**56.25 MHz 正好落回 `npu60b` 同一档余量（+0.25 vs +0.17）**，且 `DUTY0 = int(RATIO0) = 12` 是干净值。

整帧折算（W3 @54 = 1,473 ms 的整帧模型）：

| 方案 | 帧时间 | 相对 60 MHz 无预取 |
|---|---|---|
| 60 MHz，无 G2-c（现交付） | 1,326 ms | — |
| 56.25 MHz + G2-c，保守 −15% | **1,202 ms** | **−9.3%** |
| 56.25 MHz + G2-c，天花板 −27.4% | **1,027 ms** | **−22.6%**（≈0.97 fps） |

⇒ **盈亏平衡点 = G2-c 收益 6.2%**。只要 TB A/B 显示预取收益超过这个数，B' 就比现交付快，
而且**零 RTL 风险**（只改 `constraints/yeshen_mini.fdc` 的 17.778 ns 与 `board/pll_50m.v` 的
`RATIO0 11.25→12.0`、`DUTY0 11→12`），比"为重夺 60 MHz 而重构 tile 几何"（选项 C，四次前科）稳得多。

顺序不变：**先等 G2-c 的 TB A/B 数字**（`y1/build/ab_g2c/`），再决定是否起 `npu56pf` 的 PnR。

## 8. G2-c 的预取收益：装置侧第一次实测（2026-10-24）

**装置**：`AxiMemModel.v` 早在 10-23 就加了 `+RDLAT=<拍>` 读首拍延迟旋钮（默认 0 ⇔ 旧模型逐拍相同），
所以这次不需要改 TB。作业 `conv15`（32w/160×160，`COLUMNS=28900`、`GATHER_BYTES=924800`）。

| 档 | 网表 | `RDLAT` | `CYCLES` | `no_valid` | 判据 |
|---|---|---|---|---|---|
| 零延迟基线（W3 记录，当前源复现过） | `gen/UnitExec_tiled.v` | 0 | 4,549,064 | 1,246,496 | PASS |
| PF（现网表） | `gen/UnitExec_tiled.v` | 200 | **6,826,424 / 6,884,392**（两次） | 3,523,856 / 3,581,824 | **PASS**（`MISMATCH=0`、`GATHER_BYTES==GEXP`） |
| noPF（第一版对照，`pfGo` 钉 0） | `noPF.v` | 200 | **超时 >12M**（`nfed=0/1`） | — | **无效**：预取 FSM 卡在 RD 态 ⇒ 死锁，不是"慢" |
| noPF（忠于原设计的对照） | `noPF2.v` | 0 / 200 | **仿真太慢未跑完**（~570 拍/秒 vs PF 臂 ~4,200 拍/秒） | — | 未取得 |

`noPF.v` 已作废。`noPF2.v` 是把 `when_UnitExec_l2536`（预取引擎的 IDLE→SCAN 条件）钉成 0：

- **结构性证明**（不需要仿真）：`pfSt` 的其它状态只能经 SCAN 到达，而 SCAN 只能从 IDLE 进
  ⇒ `pfSt` 永远停在 IDLE ⇒ `pfGo` 永不举、`rd_ready` 的 `(pfSt===RD)` 项恒 0、`mode` 的预取项恒 0、
  `wxPfV` 永不置位 ⇒ `wxPNE = wxUse && !(wxBndV && wxBndB)`，**逐字等于 G2-c 之前的表达式**。
- 该对照臂在 iverilog 上比 PF 臂慢约 7 倍（同一 9.6 MB 网表），12M 拍看门狗下跑不完；
  **不再用仿真硬啃**，改由板级 A/B 定案（`npu60b` vs `npu56pf`）。

### 8.1 从实测能推到什么（区分实测与模型）

- **实测**：200 拍读延迟下，PF 把 conv15 压到 6.83M 拍（相对零延迟 4.55M，+50%）；
  其中 `no_valid` 从 1.25M 涨到 3.52M ⇒ **等待只吃掉了新增延迟的 40%**，预取藏掉了约 **61%**。
- **模型**（用于折算，不是实测）：无预取时每条 band 多付一次 RTT ⇒ 28,900 × 200 ≈ **+5.78M 拍**；
  故同延迟下 noPF ≈ 10.33M ⇒ **PF 收益 ≈ 1.51×（−34%）** 在 200 拍延迟下。
- **板级标定**：早前实测"每 32 B 约 1.4 µs"（L2b 之前）≈ 54 MHz 下 **75 拍**；按同一 61% 隐藏率，
  75 拍延迟下 PF 收益 ≈ **1.24×（−19%）**——仍远高于路线 B' 的盈亏平衡（6.2%）。

⇒ **路线 B'（56.25 MHz + G2-c）的收益区间：−14%（保守 75 拍）到 −29%（200 拍）**，相对现交付
`npu60b`（60 MHz 无预取，~1,326 ms）。下一步就是出这个比特流（`npu56pf`）。

⇒ 上板只要落在标定档，NPU 就从 **0.75 fps → 0.89 fps**；若 DDR 争用把有效延迟推到 200 拍，则**到 1 fps**。

## 9. 板级判定（2026-10-25 03:36）：**G2-c 在真硬件上算错 ⇒ 路线 B' 作废**

用户在 03:03 给出板级窗口。同卡同板、同一条命令（`/root/y1/y1run --frames 1`，板内分离跑）：

| 比特流 | 档 | RUN ns | 帧时间 | 输出判据 |
|---|---|---|---|---|
| `npu60b`（`6906faf1`） | 60 MHz，**无** G2-c | 1,360,223,780 | **1,360.2 ms** | **12/12 全对** |
| `npu56pf2`（`3fb1afcd`） | 56.25 MHz，**有** G2-c | 1,418,421,490 | **1,418.4 ms** | **2/12**（仅 obj_8 / obj_16 对；cls_8/16/32、obj_32、bbox_8/16/32、kps 等全错） |

**两条结论**：

1. **56.25 MHz 的 PLL 是好的**：比值 `1418.4/1360.2 = 1.043`（若仍是 60 MHz 应 ≈1.000，若 56.25 且预取无效应 ≈1.067）
   ⇒ 换算周期数 **79.8M vs 81.6M**，时钟确实降到 56.25 MHz，且预取只省了约 2% 拍数（不是装置里的 21%）。
2. **G2-c 预取在真硬件上不成立**：功能错（2/12）、收益也没兑现。

**为什么仿真闸门没抓到**（与 `npu_clk_raise.md §7.1` 的风险条目一致）：预取批与主批共用一个
DdrMaster 口，靠 `rd_ready` 的 `(pfSt===RD)` 项与 `busy` 做互斥；TB 的 `AxiMemModel` 是定拍、干净完成，
而真板经过 AXI-CDC 桥 + 2:1 仲裁 + DDR IP，**`rd_ready` 相对 `rd_valid` 的那一拍会滑动** ⇒
主批/预取批互相吞掉/多收拍，数据落错 bank。这正是"读口共用、只靠一拍互斥"的结构性缺陷，
**不是靠再调守卫能修的**（要修得让两批各有独立的完成/计数语义，即 §8 里说的"两批并行"大改）。

**处置**（本轮定案）：

- **G2-c 判死**，不交付；交付仍是 **`npu60b`（60 MHz，`6906faf1`，12/12，1,360.2 ms）**。
- 路线 B'（56.25 + 预取）**作废**；56.25 MHz 本身可用（PLL 已验证），但没有预取就没有收益，不留。
- `npu56pf2` 的比特流与 `npu56pf*` 标签**不得再用于交付**（`g2c_prefetch.md` 本行即为墓碑）。
- 若要继续追 1 FPS：必须先让"两批 gather 并行"成为**有独立 `done`/账本**的结构，并且
  **板级**先有小作业 A/B（不是只有 TB）。
