# G2 spec：中间张量改逐像素交错（NHWC band）—— 一次把 gather 的 8 个散页并成 1 段连续

日期：2026-10-22　状态：**待拍板（未动 RTL）**　前置：G1（tile 影子预取）板级 −1.94% 已回退

## 1. 为什么要换布局（实测口径）

逐单元表（`y1/reports/unit_trace_g1b3_run3.txt`，帧 2.034 s）与 RTL 结构：

| 类 | 时间 | 每像素·趟 | 读/写（名义） |
|---|---|---|---|
| conv1x1 | 869.6 ms | 11–22 拍 | 7.86 / 7.07 MB |
| depthwise | 652.7 ms | 38–44 拍 | 7.06 / 7.06 MB |
| conv3x3 | 232.1 ms | ~19 拍 | 0.32 / 1.66 MB |
| 旁路（maxpool/add/resize/sigmoid） | 279.9 ms | 7–18 拍/元素 | 2.50 / 1.99 MB |
| 合计 | 2,034 ms | — | **17.7 / 17.8 MB** |

按 `y1/reports/ddr_bridge_read_perf.md`：板级（带视频流量）有效读 ≈22–24 MB/s，冷延迟 ≈640 ddr 拍、在飞 4。
也就是说 **2.0 s 中有 ~1.6 s 是 DDR 读写**（读 17.7 MB + 写 17.8 MB），计算本身不是瓶颈。

RTL 侧的 band 结构（`UnitExec.scala`）：

- `xwBuf` = **32 列 × 8 B = 256 B，恰好一个 band**（一个 32 像素窗口）；
- band 地址 `wxRowBas = srcA + ci·inPixW·8 + iy·inWi`、`wxBB = wxGAbs & ~31` ⇒ **每平面各自一个 32 B 事务**，
  8 个平面 = **8 个不同 DDR 页**的散读；4 笔在飞 ⇒ 一个 band 至少 **2 个完整往返**（2×~640 拍）；
- 写侧为了把 `[co-block][pixel][cl]`（= 逐像素 8 通道，**本来就是 NHWC**）转成平面 `[co][y][x]`，
  走了"**逐字节取**"：8 拍才拼出 1 拍 8 B（`UnitExec.scala:1867-1943`），写相位慢 8×。

## 2. 假设（可被一次仿真 + 一次板级 A/B 证伪）

把中间张量的布局改成 **NHWC（每像素 8 通道连续）** 后：

1. 同一 band 的 8 个平面 = **256 B 连续**（同一页）⇒ AR 从 8 个散页变 2 个 128 B 事务，
   一个 band 的往返 **2 波 → 1 波**；
2. 写侧 `wOutMem` 的字序**就是** NHWC ⇒ 省掉逐字节转置，写相位从 8 拍/8 B 回到 1 拍/8 B；
3. `xwBuf` 布局（32 列 × 8 B）**不变**，只是填充来源从"8 个 32 B 散项"变成"1 段 256 B 流"。

**预测**：fill 主导的 conv1x1 / dw 各约 **1.8×**（2.07 → ~1.35–1.50 s，−27~35%）；写侧再额外若干。
**证伪条件**：若板级每 band 时间不由"波数"决定（例如被字节带宽/仲裁卡死），帧 RUN 降不到 15% ⇒ 放弃。

## 3. 设计

### 3.1 描述符

- 每个 unit 增 1 位 **`ILAY`**（本单元**输入**是 NHWC）与 1 位 **`OLAY`**（本单元**输出**写 NHWC）。
  位从"保留位"里取（`DescDefs` 冻结规则允许的保留区），不影响已有字段语义。
- 约定：
  - 第 0 个单元（读相机交付的 planar 输入）`ILAY=0`；CPU 可见输出（cls/obj/bbox/kps 四类）`OLAY=0`；
  - 其余中间张量 `ILAY=OLAY=1`（由转换器生成，相邻单元自动配套）。
- 校验（`LayerSched` 里加一条）：一个单元的 `ILAY` 必须等于其生产者（上一单元）的 `OLAY`，否则**响亮 err**。

### 3.2 读侧（gather）

- band 基址：`bb = srcA + ci·inPixW·8 + (iy·inWi + bandX0)·8`（**按像素×8**），
  band 内字节 = `(x - bandX0)·8 + plane`；
- SG 项：每 band **1 项 256 B**（`sg_beatsM1` 上限 16 拍 × 32 B = 512 B，够用；若 128 B/项则 2 项同页）；
- `xwBuf` 落数：收流按"拍内 32 B = 4 像素 × 8 通道"整段落（不再按平面分项）；列号 = `idx>>3`。
- 账本：`wxBndV/wxBndB` 由 8 平面各一条合成 **1 条**（`ci` 与 `bandX0`），`gather_bytes` 口径不变。

### 3.3 写侧（WR）

- `OLAY=1`：`wideRdAddr` 改为 `pix·NCOB_MAX + cob` 的**顺序扫描**，`wPack` 直接取字
  ⇒ 去掉 `wRdLane/wRdCl` 的逐字节相位（保留字给 `OLAY=0`）；
- `OLAY=0`：逐字节转置路径**逐字保留**（CPU 可见输出用）。

### 3.4 旁路算子

`BypassExec` 已支持 NHWC（B4 的 `conv(planar) ↔ bypass(NHWC) strided read`）；本片只需把它的读口
口径与 `ILAY` 对齐（输入 NHWC 时不再做平面→NHWC 的换算）。

## 4. 闸门（每一步都先红后绿）

1. **单元级**（`run_b1_tilebuf_ab.sh` 扩展）：
   - NHWC job 逐字节 == 冻结黄金（数值不变，仅地址序变）；
   - **AR 计数**：同一 job 的 `sg` 项数从 8/band 降到 1–2/band（本片的结构判据）；
   - 负对照：把 `ILAY` 翻错 ⇒ 逐字节 MISMATCH（必须发火）。
2. **调度级**：`ILAY == 生产者 OLAY` 校验的正/负作业。
3. **整帧**：`y1run --frames 2` **12/12 CRC 必须逐字节不变**（布局只改地址，不改数值）。
4. **上板 A/B**：基线 2,074.4 ms；用 `--unit-trace` 看 conv1x1 / dw 的 ns/pp；
   **帧 RUN ≥15% 才保留**，12/12 CRC 必过，屏画面不回归。

## 5. 切片与顺序

- **G2-a（读侧原型，仿真）**：`ILAY` 位 + gather 连续 band + AR 计数闸门；
- **G2-b（写侧原型，仿真）**：`OLAY` 位 + 顺序写 + 相邻两层联合逐字节；
- **G2-c（全表切换）**：转换器按相邻关系置位 + 校验 + 全量闸门（B1/tiling2d/NpuTop/权重信箱/dw/s2）；
- **G2-d**：dev_map → PnR → 比特流 → 上板 A/B（判据见 §4.4）。

## 6. 风险与止损

| 风险 | 对策 |
|---|---|
| DDR 侧收益不如预期（瓶颈是字节带宽而非波数） | **G2-d 之前先做一次最小板级 A/B**（只切 Conv_12→Conv_15 两层），Conv_15 的 ns/pp 降不到 25% ⇒ 停 |
| 描述符位污染冻结字段 | 只用保留位；`run_desc_ab.sh` + 非法表负对照必过 |
| CPU 可见输出布局被误改 | `OLAY` 默认 0；四类输出的 CRC 闸门（12/12）是硬判据 |
| 面积/时序 | xwBuf 不变；写侧省逻辑；预估 LUT 持平或更小；dev_map LUT ≤60%、DRM 不变 |
| 转换器/驱动错位 | arena 大小不变（每单元区域按字节数不变），只改字节序；per-unit CRC 对比 |

**止损**：G2-d 若 <15% ⇒ 回退全部 G2 改动并留档（与 G1 同一套净结算）。

## 7. 与其它杠杆的关系

- G1（影子预取）已证：dense 不是 fill 延迟受限，藏延迟无收益 ⇒ **不要再做延迟隐藏**；
- 本片改的是**每次往返搬运的字节数与页局部性**（不是延迟、不是队列深度）；
- P3/P6 已证：加深队列/在飞无效（DDR IP 在飞 ≤4）⇒ 与 G2 不冲突，G2 不依赖队列深度。

## 8. P0 实测（2026-10-22/23，**只动装置**，未动 DUT）

给 `rtl_test/UnitExecWideTb.v` 加了**分相拍数**（`PHASE fetch/emit/decide/wr`，按 `wxSt` 采样，
`fetch` = 等 band、`emit` = 喂列、`decide` = 判 band），用同一 tiled 作业（64/64，40×40，8×8 趟）跑：

| 档 | CYCLES | fetch | emit | decide | 其余（装载/写回等） | AR |
|---|---|---|---|---|---|---|
| 内存零延迟（原始模型） | 1,836,614 | 39,360（**2.1%**） | 1,193,536（**65.0%**） | 125,424（6.8%） | 478,294（26.1%） | 6,208 |

**结论 1**：**零延迟下 gather 的 fetch 只占 2%**，宽路是 **emit（切片消费节拍 ~4 拍/列）主导**。
⇒ "gather 延迟 = 全帧 80%" 在带 tileBuf/B1 的当前 RTL 上**不成立**（那是 P1 时代的合拟合）。
板级 Conv_15（80×80）166 ms vs 同作业零延迟外推 ~57 ms ⇒ 内存停滞约占 2/3、但不是全部；
G1 只值 −4%（conv1x1）与这条吻合。

**结论 2（未完成）**：为了量"延迟敏感度"，给 `AxiMemModel` 加了 `+RDLAT`（每笔读先等 N 拍），
但 **LAT>0 时装置会卡在 `SGRUN/busy=1/rd_valid=0/rd_ready=0`（模型侧 bug，未修）** ⇒ 该档数据作废，
模型改动已回退（分相计数保留）。**在拿到可用延迟档之前，不启动 G2 的 RTL 改动。**

**下一步（二选一，先做便宜的）**：
1. 修 `+RDLAT` 模型的卡死（TB-only），拿到 LAT=80/320/640 的周期曲线 —— 若 LAT=640 下周期涨 ≥1.8×，
   NHWC/减少 AR 数就有明确上限，再动 RTL；
2. 或把分相计数做成板上只读 CSR（HOST 可读），直接量板级 `fetch/emit` 比例（要一次 PnR）。

### 8.1 延迟档排查结论（2026-10-23，模型改动已回退）

`+RDLAT>0` 时装置在**第一 band 之后就不再发任何 AR**（模型统计 `bursts=8`，DUT `wxSt=FETCH`、
`ddrMaster idle`），而不是慢。结合 gather 的结构（DECIDE→整 band 入队→等 `done`→EMIT→下一 band）：

- **gather 是"整 band 收齐才发下一 band"的硬串行**：一个 band 的一次完整往返无法被任何后续 band 掩盖；
- 因此**换布局/减少 AR 数（NHWC）只能缩短这次往返的传输部分，减不掉往返本身**（上限有限）；
- 真正对症的是 **band 级前瞻/双缓冲**：`xwBuf` 扩成 2~4 个 band、SG 队列入队下一 band 的项，
  在当前 band 喂列（emit）时就把下一 band 的 AR 发出去 ⇒ 把"往返"藏进"喂列 + 上一条 band 的传输"。
  这是比 NHWC 更小、更直接的改动（只动 gather FSM + xwBuf + rqDepth），建议作为 G2 的替代方案（G2-b）。
- 量化前提：需要先有一个可用的延迟模型（或板上分相计数）；本轮的 `+RDLAT` 模型在 LAT>0 时
  装置行为不可信，**不据此下收益结论**。
