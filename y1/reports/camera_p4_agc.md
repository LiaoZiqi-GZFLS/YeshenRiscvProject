# Y1 相机画质：移植 cam2lcd P4（AGC 1× + 曝光 1216）

状态：RTL 常量已改，dev_map/PnR 进行中；**未上板**（等相机线窗口）。

## 1. 结论与依据

cam2lcd 那条线治“暗场色偏 + 彩噪闪烁”的有效改动是**传感器初始化表**，不是高斯
（用户最终认可的是 `cam2lcd2_top_p4_nogauss.sbit`，md5 `5df46d6b…`）。
其交付报告 §4/§8 的原话：**“关自动增益：暗场 AGC 拉满放大暗电流成彩噪闪烁”**，
P4 口径 = **AEC 自动 + AGC 上限 1× + 最大曝光 1216 行（< VTS 1224）**。

对比（`camera.v` / `camera_data.v` / `SCCB.v` 两边逐字节相同，差异只在 `data_init.v`）：

| 寄存器 | Y1 改前 | Y1 改后（= P4 口径） |
|---|---|---|
| `3A18/3A19` AGC 最大增益 | `00/20` = 2× | **`01/00` = 1×** |
| `3A02/03`、`3A14/15` 最大曝光 | `17/10` = 0x1710 | **`04/C0` = 0x04C0 = 1216 行** |
| `3503` AE/AGC/VTS | `04`（VTS 手动，AEC/AGC 自动） | **保持 `04`**（锁帧率） |
| `350A/B` 增益 | `00/10` = 1× | 保持 |

## 2. 改动（唯一文件）

`board/cam/vendor/camera/data_init.v`（本仓自己的厂家副本；被参考仓库零改动）：

- `cfg[29] 3A18: 00→01`、`cfg[30] 3A19: 20→00`；
- `cfg[230] 3A02: 17→04`、`cfg[231] 3A03: 10→C0`、`cfg[232] 3A14: 17→04`、`cfg[233] 3A15: 10→C0`。

**不搬** cam2lcd 现在的 254–266 项（AWB B=1.5 / VTS 2448≈14 fps）——那是 `p4_15fps`
实验，不在 `p4_nogauss` 里；**不加**水平 1×3 高斯（用户偏好无高斯）。

## 3. 影响面

- 纯常量表：无逻辑/时序/面积变化；CPU/NPU/显示时序链路不动。
- 画面：暗场不再被 AGC 抬到 2× 放大彩噪；代价是暗场整体**暗约一档**（1× 增益）。
  若现场太暗，可做 1.5×/2× 上限对照版（同样只改 `3A18/19`）。

## 4. 验证

1. `iverilog -g2005 -t null data_init.v`：**PASS**。
2. dev_map（tag `video1p4`）：0 error / 资源不越线。
3. PnR（tag `video1p4`，speed）：All constraints met + 比特流。
4. 上板目视 A/B（等窗口）：同场景对比当前 Y1 画面，看色偏/杂闪是否消失；
   回退 = 还原 6 个常量重烧，或直接烧回上一版 Y1 比特流。

## 6. 2026-10-21 追查：Y1 屏幕杂色 —— 与 cam2lcd 交付版逐条对齐

**现场证据（板级）**：把 Y1 帧存（`0x9000_0000`）按 640×640 抽出来看，
**抓到的帧本身就是花的**（不是 LCD/仲裁器）：
- G 字段（bits[10:5]）单独看是**干净的灰度场景**；R[15:11]/B[4:0] 是高频杂色；
- 两帧相差 ~3.7 s：31% 字节相同、mean|d|=25 ⇒ 逐帧不稳定（对应"闪烁"）。

**与正确版本（cam2lcd `eed3b59`，交付 `5df46d6b`）逐条比**：
- vendor 视频 RTL 全部逐字节相同（camera/cmos_8_16bit/camera_data/SCCB/wr_ctrl/rd_ctrl/sync_vg；
  fram_buf/rd_buf 只多了本工程的 `ROW_OFFSET` 参数）。
- 相机寄存器表 **254 条里只有 1 条不同**：`0x3503` = Y1 `0x04`（VTS 手动） vs 交付版 `0x00`（全自动 AEC/AGC/VTS）。
- 本工程另有：居中裁列 128..1151（交付版 0..1023）、ROW_OFFSET=60、overlay、DDR 2:1 仲裁器。
  视频读等待计数在空闲时几乎不涨（10 s ≈ 1.9k/65536 回绕）⇒ 仲裁器没有饿死 LCD。

**处置**：
1. `0x3503` 改回 `0x00`（与交付版逐字一致），重跑 PnR `video1p5`（同带 P4 仲裁器）。
2. 已把交付版 `cam2lcd2_top_p4_nogauss.sbit`（`5df46d6b`）烧回板上做**现场对照**：
   若参考版画面现在也花 ⇒ 先查**相机接线（必须直插，杜邦线会引入固定列数据错误+偏色，厂家报告 §7）**；
   若参考版正常 ⇒ 差异只在 Y1 带内，按 3503 / 采相位 / 颜色测试图案（0x503D=0x80）逐项二分。

**收口（2026-10-22，`video1p5`）**：0x3503 改回 `0x00` + P4 仲裁器后，屏上画面**正常（用户确认）**。
同带 `y1run` 2.0744 s（−4.3%）。相机表与 cam2lcd 交付版 `eed3b59` 现**逐字一致**（254 条全同）。
