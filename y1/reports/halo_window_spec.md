# H1 spec：窗口 halo 与 band 对齐（去掉 2.8× 取数放大）

日期：2026-10-23　状态：**待实施**　前置：G1/G2-b 已回退；交付基线 2,074.4 ms

## 1. 实测/静态事实

tile 的输入窗口是 `nCol = s·tw + 2`、起点 `tFx = tOx0·s − s`（`UnitExec.scala:890`），
即**左 halo 1 列 + 输出 tw 列 + 右 halo 1 列**。而 `tOx0` 是 32 的倍数 ⇒ `tFx = 31`（s=1）时
34 列窗口跨越 **3 个 32 B band**（`[0,32) / [32,64) / [64,96)`）：

- 每行每平面取 **96 B**，真正需要 34 B ⇒ **2.82× 取数放大**、**3 次往返**（band 粒度）。
- **实测基线**（conv15：32→64、160×160、25 满 tile、4 ci-block、LAT=0）：
  `CYCLES=7,876,639`、**`FETCH=1,548,288 B` / 交付 `924,800 B` = 1.674×**、`AR bursts=99,584`。
  （比静态 2.82× 低：B2 列 shadow 已替内部 tile 省掉"左 halo 那个 band" ⇒ 实际 **2 band/行**，
  但其中 1 个 band 只有 2 列有用。）
- 这些垃圾字节同时吃 DDR 带宽：conv1x1 名义读 7.86 MB → 实际取数 ≈ 3×（G2-P0 已证板级受带宽限制）。

## 2. 改法（两档，互不冲突）

### H1a：**纯 1×1 单元无 halo**（最高价值）

1×1 不需要任何 halo（`one_x1` 只取中心）。把 halo 从 1 变 0：

- `tFx/tFy = tOx0·s − s·h`、`tNCol/tNRow = s·tw + 2h`（h=1 现状；h=0 无 halo）；
- 收料窗口 `tKeepW` 与输出下标 `tOutIdxW` 改成以 `h` 为基（现为 `>=1` 与 `-1`，改成 `>=h` 与 `-h`）。

判据条件：`dw.tpe == CONV1 && io.chain_len == 1`（**纯 1×1**；融合对的尾是 CONV3，不受影响）。

效果：窗口 = 32 列 = **1 个 band/行**（从实测的 2 个）⇒ **取数往返 2→1、字节 64→32 B/平面/行**；
预测 `FETCH ≈ 870,400 B`（**−44%**）、AR 包数近似减半。

### H1b：3×3/dw 用 B2 shadow 跳过"左 halo band"

3×3 的窗口仍需 34 列，但**左 halo 那 1 列已在 B2 列 shadow 里**（tile 边界重叠）。
把"取 band"的判据从"本行窗口起点所在 band"改为"窗口内**第一个需要真取的列**所在 band"：

- 首 tile（`tTx==0`）左 halo 是 pad ⇒ 本来就该跳；
- 内部 tile 左 halo 由 shadow 命中 ⇒ 跳过 `[tFx&~31]` 那个几乎空的 band；
- 每行 3 band → **2 band**（−33% 字节与往返）。

风险：B2 shadow 只在 `s=1` 且 `nCi ≤ 槽数` 时开 ⇒ 条件不满足时退回现状（保守）。

## 3. 闸门

1. **单元级**：conv15（x1）逐字节 == 冻结黄金；`GATHER_FETCH_BYTES` 应从 2.82×GEXP 降到 ≈1.0–1.1×GEXP；
   `AR` 数同步下降；`GATHER_BYTES`（交付列）在 H1a 下会从 34 列/行变 32 列/行（**gate 的 GEXP 锚要按 h 重算**）。
2. **负对照**：把 h 强制回 1 ⇒ 数字回到现状、逐字节仍对（红点唯一：只有计数/周期变）。
3. **回归**：c64_40（3×3）、tiling2d（s1 六几何 + s2）、NpuTop 调度、权重信箱；`TILING=false` 三份 md5 冻结。
4. **板级**：`y1run --frames 2` vs **2,074.4 ms**；≥5% 才保留、12/12 CRC、屏不回归。

## 4. 预期与止损

- conv1x1（870 ms，43%）取数从 1.67× 降到 1.0×（−44% 字节、−50% 往返）⇒ 若 fill 份额 ~20%，
  省 **~90–140 ms（−5–7%）**；
- H1b 对 dw/3×3 再 −33% 取数（655+232 ms 中的 fill 部分），合计有望 **−8–12%**；
- **止损**：板级 <5% ⇒ 回退；任何 CRC 红 ⇒ 立即回退。

## 6. 实施结果（2026-10-23）：**H1a 挂死，已回退**

改点按 §5 全部落地（6 处 `if (TILING)` 门控，`TILING=false` 三份 md5 保持冻结），但单元闸门
（conv15，LAT=0）**12M 拍超时**：`MEM rd=42,240 B`、`bursts=1,320` 后停住。

判断：无 halo 后 `tNCol/tNRow/tKeepW/tOutIdxW` 与宽路 feed 的**合成 pad 行/列契约**
（`wRow === inRows` 的 z_pad 行、`tOutPerRow` 口径）不再自洽 ⇒ gather 走到某个边界后不再发 AR/不再交付。
这条不只是一处改点，需要连带改 feed/收工的 pad 语义，超出"窗口参数化"的范围。

**处置**：源码已回退，网表重生成后 `TILING=false` 三份仍 `7593b189/817ab5bb/5d2cd81a`、
`UnitExec_tiled` 回 `f01da4da`。

**保留的实测证据**：conv15 基线 `CYCLES=7,876,639`、`FETCH=1,548,288 vs 交付 924,800 = 1.67×`、
`AR bursts=99,584` ⇒ 1×1 层取数放大确认为 **1.67×**（两个 band/行，其中一个只有 2 列有用）。
要做这个收益，正确路径是**改 feed 的 pad 契约**，不是在窗口参数上打补丁。

## 7. H1a'（halo 列强制 pad）：**数值错，已回退**（2026-10-23）

为避免动几何，改为只把纯 1×1 的左右 halo 列强制当 pad（不取数、交付 `z_pad`）。结果：
- `FETCH 1,548,288 → 860,160 B（−44.4%）`、`CYCLES 7,876,639 → 7,739,487（−1.7%）`、`RESULT PASS`；
- 但逐字节 **`MISMATCH=40,536 / 1,638,400`** ⇒ **halo 列是输出映射的承重**：
  1×1 的切片窗口是**居中**的，每个 tile 行的**首列输出**读到窗口的第 0 列（= 左 halo），
  把它换成 `z_pad` 就错。右 halo 同理影响末列。

**结论**：1×1 的 halo 不能"只当 pad"，也不能"去掉"——两者都会移动输出的列相位。
要吃到 −44% 的取数收益，必须**同时改输出映射**（`tKeepW/tOutIdxW` 与切片居中相位），
这不是局部改动；本轮到此为止，源码与网表已回退（`7593b189/817ab5bb/5d2cd81a` + `f01da4da`）。

**可复用的实测**：该改动已证明 `FETCH −44%` 与 `CYCLES −1.7%`（LAT=0）是可实现的，
且 `GATHER_BYTES` 交付口径不变——只要解决好列相位，收益就在那里。

## 8. 右 halo 才是承重（2026-10-23，决定性）

去掉左 halo（`wCol==0`）与去掉右 halo（`wCol==tNCol-1`）两版**单独**验证：

| 版本 | FETCH | CYCLES(LAT=0) | 逐字节 MISMATCH |
|---|---|---|---|
| 基线 | 1,548,288 | 7,876,639 | 0 |
| 两侧都 pad | 860,160（−44%） | 7,739,487 | **40,536** |
| **只 pad 右 halo** | 860,160 | 7,739,487 | **40,536（完全相同）** |

⇒ **误差全部来自右 halo**：tile 行**末列输出**读窗口最后一列（右 halo），它必须真取；
而左 halo 是死的（且已被 B2 列 shadow 免费覆盖）。**因此 1×1 的 −44% 取数是拿正确性换的，不可用。**

**结论（这条线封存）**：窗口 34 列、起点 `tOx0−1`（31 偏移）⇒ 33 个有用列必然跨 2 个 32 B band，
**1.67× 放大是 32 B 颗粒度 + 偏移的结构性代价**，不是可以局部省掉的浪费。要真正省，只能
(a) 改几何让 33 列落进同一个 32 B 对齐窗口（H1a：与 feed 的 pad 契约耦合，实测挂死），或
(b) 让多个 band 同时在飞（G2-b：需要 `DdrMaster` 批 owner）。两者都是结构性重做。

源码与网表已回退（`7593b189/817ab5bb/5d2cd81a` + `f01da4da`）。
