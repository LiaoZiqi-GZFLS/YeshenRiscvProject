# Y1-NPU B2 设计图：B1 之后**剩余的输入读放大**（tile halo / dw 对角趟 / s=2 缺口）

- 日期：2026-10-20　**基线**：`master` @ `becf9e9`（B1 已上板：`y1run` 4.5096 s → 3.1475 s，12/12 CRC OK）
- 上游：`docs/superpowers/specs/2026-10-20-y1-npu-b-input-reuse-design.md` §4「后续」、
  `y1/reports/b1t2_tilebuf.md`（§3 计数口径、§7.2 闸门）、`y1/reports/b1t1_map.md`（§3.4 halo/band、§6.2 风险）
- **性质**：**只读设计图**。不改 RTL、不重生成网表、不碰板、不 push。本片只提交本文件。
- **一句话结论**：B1 之后每帧输入读 = **19,767,296 B = nominal×1.2972**（交付口径）。剩余放大只有两块：
  **① tile halo 2,378,496 B**（其中**真·跨 tile 重读 2,067,792 B**，其余 310,704 B 是 pad 环 —— 计量器数、DDR 不读）；
  **② 宽层 dense 仅剩的一处 co-block 重读：`Conv_0`（s=2）1,228,800 B**。
  spec §4 点名的「dw 对角趟复用」**在 RTL 里已经满足**（每 ci-block 每 tile 只读一次）⇒ 那一项是空的；
  dw 的 978,096 B halo 要走**逐 ci 的列 halo shadow**（不是 tileBuf）。⇒ **B2 值得做，但要重新划范围**（见 §5）。

### 1.1 (a) tile halo：32×32 tile + 2 行/列 halo，**每对相邻 tile 重叠 2·s 列（或行）**

几何（全部在 `y1/rtl/UnitExec.scala`）：

| 量 | 值 | 行号 |
|:--|:--|:--|
| tile 输出尺寸 | `WT=WIDTH-2=32`、`HT=IMG_H_MAX=32`；`s=2` ⇒ `WT=(WIDTH-2)/2=16` | `:867-868`、`:913-915` |
| 窗口尺寸 | `tNCol = s·tw+2`、`tNRow = s·th+2`（`s=1` ⇒ 34×34；`s=2` ⇒ 34×66） | `:892-894` |
| 窗口起点 | `tFx = s·(ox0-1)`、`tFy = s·(oy0-1)`（`ox0=0` ⇒ 起点 −s，即 pad 环） | `:885-891` |
| tile 网格 | `tNtx=⌈Wo/WT⌉`、`tNty=⌈Ho/HT⌉`；末 tile 的 `tw/th` 可以更小 | `:887-888`、`:1974-1976` |
| tile 循环推进 | tile 在最外层，每 tile 重跑全部趟：`wtTileDone` ⇒ `wSt:=0; wCob:=0; wCi:=0` | `:2223-2231` |

**重叠量**：相邻 tile 的窗口步长 = `s·32`，窗口宽 = `s·tw+2` ⇒ 满 tile 时重叠 **`2·s` 列**（`s=1`: 2 列 / `s=2`: 4 列），
行同理。一个 tile 的窗口比它自己的输出多 **132 格**（`s=1` 满 tile：`2 行×34 + 2 列×32 = 132`，占 1156 的 **11.4%**）。
这 132 格**不是**均匀的「重读」：
- **左 1 列（32 格）+ 上 1 行（32 格）** = 左邻/上邻 tile **刚刚读过的同一批字节** ⇒ **真·重读**；
- **右 1 列（32 格）+ 下 1 行（32 格）** = **新字节**（它们会在下一个 tile 再被读一次，见下一行的口径）；
- 图像边界的那些格子是 **pad**（`wxPad`，永不发 AR）。
全层折算（160²，25 tile）：`25×132 = 3,300` 格/平面，其中 **2,624 格是真·重读、676 格是 pad**
（对 `Conv_15` 的 32 平面 = 84,480 + 21,632 = **105,600 B**，与 §2.3 的 `Conv_15` halo 逐位相同）。
★ 本片的重读口径按「**同一批字节被 gather 两次**」定义 ⇒ 全帧 = **2,067,792 B**（右/下那半边在下一 tile 里
被记成左/上，不重复计）。

按形状的实测窗口和（`Σ_tiles tNRow·tNCol / (H·W)`，本片用真表几何算）：

| 形状 | tile 网格 | `Σ window / area` | 单元数 |
|:--|:--|--:|--:|
| 320×320 | 10×10 | **1.128906** | 2 |
| 160×160 | 5×5 | **1.128906** | 8 |
| 80×80 | 3×3（34+34+18） | **1.155625** | 14 |
| 40×40 | 2×2（34+10） | **1.210000** | 14 |
| 20×20 | 1×1（22） | **1.210000** | 14 |

⇒ 交付口径的 halo = **2,378,496 B**（nominal 的 ×0.156），拆开：
- **真·跨 tile 重读（同一批字节第二次被 gather）= 2,067,792 B**；
- **pad 环（计数有、DDR 没有）= 310,704 B**（`wxPad` 列不参与 `wxPNE` ⇒ 不发 AR，`UnitExec.scala:1693,1698`）。

> 注意：halo 与 `nCo` **无关**（B1 之后每个 ci-block 只读一次），所以它按「每 ci-block × 窗口」线性计。

### 1.2 (b) depthwise 对角趟：**每 ci-block 每 tile 只读 1 次**（spec 那一项已是 no-op）

| 事实 | 行号 |
|:--|:--|
| `isDwW = (group≠0) && (group==C_in) && (C_in==C_out)` | `:1406` |
| 换趟 = **对角** `(wCob+1, wCi=wCob+1)`，跑完末 co-block 收工 | `:2157-2159` |
| 收料门 `wCollectCiOk = Mux(isDwW, wCi==wCob, wCi==nCi-1)` | `:1845` |
| 偏置门 `wCi==0` 或 `isDwW`（每个 co-block 的唯一一趟都带本块 bias） | `:1786-1787` |
| `ps_clr = tilingW && Mux(isDwW, True, wCi==0)`（每趟从 0 起） | `:2364` |
| gather 的平面基址按**当前 `wCi`** 取 ⇒ 第 b 趟只读第 b 个 ci-block | `:1680`（`wxPl0 = srcA + wCi·(tInPixW·8)`）、`:1658-1661`（`wxNPl`） |
| 趟数自报 `wide_passes = Mux(isDwW, nCo, nCi·nCo)` | `:2721` |

**结论**：一次 run 的 dw 输入读 = `Σ_tiles nRow·nCol · C_in`（每 tile 把 C_in 个平面**各读一遍**，
`nCo` 趟各读自己那 8 个平面）⇒ **每个 co-block 1 次、每个 ci-block 1 次、没有跨 co-block 重读**。
真表 20 个 dw：交付 8,033,296 B，其中 **halo 978,096 B（12.2%）**，重读 0。
⇒ `spec §4` 的「dw 对角趟输入复用」**RTL 已满足，B2 不需要为它做任何事**（dw 的真实浪费在**tap 拍**：
`reports/npu_v2_mac_table.txt` 的 P0b 类账 dw `issued/ideal = 8.10×`，那是计算侧，不是读）。

### 1.3 (c) odd / narrow 形状

| 项 | 单元数 | 输入读是否有额外放大 | 依据 |
|:--|--:|:--|:--|
| `C_out % 8 != 0`（10/4/1 通道） | **24** | **无**。输入平面数只由 `C_in` 决定；末 co-block 只是**计算侧**部分尾块（WR 按 `C_out·H·W` 截断） | `:1464`（`wideCoRows`）、`:2406-2410`（`wtCo` 推进） |
| `C_in % 8 != 0`（3/1/4/10 通道） | **13** | **无**。末 ci-block 只读 `Npl = C_in−8·cib` 个平面（`wxNPl`），跳过的通道**不发 RD** | `:1658-1661`、`:1689-1696` |
| `nCo == 1`（`C_out ≤ 8`） | **18** | B1 对它**零收益**（本来就没有 co-block 复用可做）；**halo 照常存在** | `:3024` |
| 小 H/W（20²、40²） | 28 | 无「重读」新增，但把 halo 倍率抬到 **1.21×**（tile 越碎，halo 占比越高） | §1.1 表 |
| `s = 2` | 1（`Conv_0`） | **有**：B1 不覆盖 ⇒ co-block 重读 **1,228,800 B** | §1.4 |

⇒ (c) 本身**不产生**新的「同一批字节读多次」，它只是把 (a) 的倍率抬高。**B2 不为 (c) 单独改 RTL**；
唯一与 (c) 有关的动作是：B2 的 halo shadow 必须**按 `wCi` 分槽**（否则 `C_in%8!=0` 的末块会把 8 lane
的零 lane 也写进 shadow，重放时拿到别人的通道）。

### 1.4 (d) dense 路径剩余的 co-block 重读：**只剩 `Conv_0` 一个**（s=2 被 `tS==1` 门挡掉）

- 门：`UnitExec.scala:3024` 的 `(tS === U(1,4))` ⇒ `s=2` 不进 B1。缓冲也不够：`b1Depth = WIDTH·(IMG_H_MAX+2)`
  = **1,156 字 = 9,248 B**（`:3018`），而 `s=2` 的窗口 = **34×66 = 2,244 字 = 17,952 B**（`tNCol=2·16+2=34`、
  `tNRow=2·32+2=66`，`:893-894`）。`b1Addr = wRow·WIDTH + wCol`（`:3035`）在 `wRow=65` 时 = 2,243 ⇒ 越界。
- `Conv_0`：`nCi=1`、`nCo=2`、`tS=2` ⇒ 每 tile **2 趟**（`(0,0)` 与 `(0,1)`）**各读一遍同一个 34×66×3 窗口**。
  tile 网格 20×10 = **200 tile**；每 tile 每趟读 `2,244×3 = 6,732 B` ⇒ 全层
  `200 × 2 × 6,732 = 2,692,800 B`，其中 **1,228,800 B 是纯 co-block 重读**（= 真输入 1,228,800 × 1）。
  对照：B1 的交付口径 19,767,296 里，**这一项占 6.2%**，但它同时是**交付列数的 14.7%**（897,600 列 / 3,061,360 列）。

**明写的两处不确定性**（这是本片最重要的诚实项）：

1. **R4（冷突发 2.08 µs）比 R2（0.64 µs/突发）贵 3.3 倍**。区别是 B1 去掉的突发是**同地址重读**（DRAM 行
   打开、延迟短），而 B2 要去的突发是**冷**的。当前帧 `1,514,280 × 2.08 µs = 3.1475 s` **逐位吻合**
   ⇒ 现网表**几乎完全被「一次一笔 32 B 突发」串行化限住**（8 个平面的 FETCH 是**串行**的：
   `:2322-2344` 每平面 `wxK` 认领 → 等 `done` 才放下一个平面）。若这条成立，B2 的收益在上界（R4）。
2. 若真实是「每交付列固定 ~0.4 µs（与突发无关）」，则 **列 halo 的收益 ≈ 0**，只剩 (d) 的 0.18 s。
   ⇒ **B2 的闸门必须先把这一条量出来**（§4 的 CYC 计数器），而不是在板上赌。

## 3. 最小编辑集

### 3.1 B2a：`s=2` 的 tileBuf 扩展（**2 行**，把 dense 最后一处 co-block 重读消掉）

| # | 位置 | 改动 |
|:--|:--|:--|
| ① | `UnitExec.scala:3018` | `val b1Depth = WIDTH * (IMG_H_MAX + 2)` → `WIDTH * (2*IMG_H_MAX + 2)` = **2,244 字 = 17,952 B**（`b1Aw` 11→12） |
| ② | `UnitExec.scala:3024` | `b1Use := tilingW && !isDwW && (tS === U(1,4))` → **去掉 `tS` 项**：`tilingW && !isDwW` |

**为什么这就够（可推）**：
- `b1Addr = wRow·WIDTH + wCol`（`:3035`）对 `s=2` 的上界 = `65·34+33 = 2,243 < 2,244` ⇒ 不越界；行跨步仍是
  常数 `WIDTH=34`，而 `s=2` 的 `tNCol` 恰好也是 34（`2·16+2`）⇒ **地址形状不用改**；末 tile `tw<16` 时
  `tNCol<34` ⇒ 缓冲内稀疏但仍在界内；`b1AddrS` 的 `wRow ≥ tNRow ⇒ 0` 钳位（`:3037`）照旧防尾排空越界。
- 重放/填充逻辑（`:3029-3060`）**一字不改**：`b1Play = b1Use && wCob≠0`、`b1Fill = b1Use && !b1Play`——
  `Conv_0` 是 `nCi=1`，ci-outer 重排（`:3065-3071`）在 `nCi==1` 时**与旧序完全相同**（`wCi` 恒 0），
  所以**唯一的行为变化**就是「第 2 个 co-block 从 tileBuf 重放、不再发 AR」。
- `ps_clr`（`wCi==0`，`:2364`）、收料门（`wCi==nCi−1`，`:1845`）、`wBiasR`（`wCi==0||isDwW`，`:1786-1787`）
  在 `nCi=1` 下**两趟都为真** ⇒ 与旧行为逐位同义（每 co-block 一趟、从 0 起、带本块 bias）。
- 数值等价性 = B1 对 `s=1` 证明过的那条（同一组交付列、同一累加顺序），只是换了一个窗口尺寸。

**代价**：buffer 9,248 → **17,952 B**（+8,704 B ≈ +2 DRM；当前 PnR 实测 `DRM 255.5/415 = 62%`、
`LUT 47.5%`，见 `y1/pds/pnr_c4a_cpufast.log:16617,16624,18001`）⇒ **不是瓶颈，但必须 dev_map 记账**。
地址锥从 11 位加宽到 12 位（常数乘 34）⇒ 多约 1 级 LUT，需 `dev_map`/时序复核。

### 3.2 B2b：列 halo 复用（**每 ci 一份 2 列 shadow**，dense + dw 共用，4,352 B）

**为什么不是「把 B1 tileBuf 留着 2 行」**：B1 的 tileBuf 是**单份、按当前 ci-block 覆盖**的：

| 障碍 | 证据 |
|:--|:--|
| 每次填充只装**一个** ci-block（重放趟读它），换 tile 时最后装的是 `ci=nCi−1` | `:3020-3021`（单条 `b1Buf`）、`:3029-3033` |
| 所以第 2 个 tile 的 `ci=0` 填充开始时，tile0 的 `ci=0` 数据早被 `ci=1..nCi-1` 覆盖 ⇒ **单缓冲留不住跨 tile 的 halo** | 同上 |
| 行 halo 想在 `ty→ty+1` 复用，还要 tile 遍历次序是「列优先」；当前是 **tx 内层**（`tTx` 先加） | `:2226-2230` |
| dw 更是**对角趟**：下一个 tile 的同 ci 数据被中间 7 趟覆盖 | `:2157-2159` |

⇒ 用**专用 shadow**（不是把 tileBuf 改大）：每个 ci-block 存 **2 列 × (IMG_H_MAX+2=34) 行** 的一列向量：

```
b2Halo   : Mem(Bits(C*8), NCOB_MAX*2*(IMG_H_MAX+2))   // 8*2*34 = 544 字 = 4,352 B
addr     = wCi[2:0]*(2*34) + (wCol-(tNCol-2))*34 + wRow      // 写：填充趟的最后 2 列
读       = wCi[2:0]*(2*34) + wCol*34 + wRow                  // 读：填充趟的最前 2 列（tTx>0）
```

| # | 位置 | 改动 |
|:--|:--|:--|
| ① | `:3013-3079` 节内新增 | `b2Halo` Mem（4,352 B）+ `b2Hit`/`b2Fill` 两个 `Bool`（`setName`，供网表一行突变） |
| ② | `:3040-3041` | `b1Acc` 写 tileBuf 的同时，`when(b2Fill && wCol >= tNCol-2 && wRow < tNRow)` 写 shadow（**同一组交付列**，不新增读源） |
| ③ | `:3057-3060`（重放覆盖）旁 | 追加：`when(WIDERUN && wSt==3 && b2Fill && b2Hit && wxSt==1) { wxSt := 3 }`（**DECIDE→EMIT，不 fetch**）——与 B1 重放**同一招**（`:3043-3053` 的时序论证逐字适用） |
| ④ | 同上 | `when(... b2Fill && b2Hit)` ⇒ `mpu.io.x := shadowWord`（对 `wxCol` 的后写覆盖；`b1Play` 的重放覆盖优先，两者互斥） |
| ⑤ | `:3074-3078` 旁 | 新增**取数口径**计数器 `gather_fetch_bytes`（FETCH 完成时 +32），与 `gather_bytes`（交付口径）并存 |

- `b2Fill = tilingW && (b1Fill || isDwW)`（dw 没有 `b1Fill`，`b1Use` 里带 `!isDwW`），`b2Hit = b2Fill && (tTx>0) && (wCol<2) && (wRow<tNRow)`。
- **槽号用 `wCi` 而不是 `wCob`**：dense 的填充趟是 `(cib, cob=0)`（`wCi=cib`），dw 是对角趟（`wCi==wCob`，`:2159`）
  ⇒ 一个下标两档通用；`s=2` 的 `nCi=1` 也只占槽 0（不做 halo）。
- `tS==1` 门：`s=2` 的列 halo 与 `Conv_0` 的窗口/`tWT2=16` 一起会破坏「前 2 列 = 邻 tile 后 2 列」的对齐
  （`s=2` 的重叠是 **4** 列）⇒ **B2b 只开 `s=1`**，`Conv_0` 交给 B2a（它的 235,200 B halo 留着）。
- **为什么只做列、不做行**：行 halo 在取数口径只值 **4.8%**（2/34 行，且每行仍要自己的 band），
  而列 halo 在 `80²` 形状上是 **7→3 band（−57%）**、`160²` 是 **13→9（−31%）**（因为列 halo 恰好落在
  band 边界外：内 tile 的 34 列窗口首列总在**上一个 32 B band** 的尾巴上）。⇒ **列是唯一有 AR 价值的半边**。
- **dw 能不能共用**：**能，而且必须按 ci 分槽**（B2b 的 shadow 就是按 `wCi` 分槽）⇒ dw 的 978,096 B halo
  一并消掉，且**不改**对角趟次序（`WIDE_PASSES == nCo` 的既有判据不动，`run_dw_wide_ab.sh`）。
- 交付列数**不变**（halo 列仍要交给 `mpu`，只是不 fetch）⇒ `tKeepW`/`wxPixTot`/`wEmitCnt`/PSB 段基址
  （`PartialSumBuf.scala:20-24`、`MultiPassUnit.scala:169`）**全部不动** —— 这是本方案最大的安全边界。

## 5. 判定（go verdict）与到 ≥0.5 fps 的路径

> **总判定：AMBER（有条件 go）**——按**重新划过的范围**执行：**B2a 绿、B2b 有条件绿**、行 halo 与
> 「dw 对角趟复用」不做。**不要**把 B2 理解成 spec §4 的原方案（它有一半不可行、另一半已是事实）。
> 顺序：**G7 标定 → B2a → B3 →（按标定）B2b 进 PnR**。

### 5.1 逐项判定

| 项 | 判定 | 理由 |
|:--|:--|:--|
| **(d) `Conv_0` s=2 的 co-block 重读（B2a）** | **GREEN** | 2 行改动、复用已证的 B1 重放路径、`nCi=1` 使趟序重排退化；省 1,228,800 B / 448,800 列 / 2.47 MB 突发（0.05–0.18 s，梯子交叉校验 0.18–0.37 s） |
| **(a) 列 halo（B2b）** | **AMBER（有条件 go）** | 省 2,067,792 B / **15.3 MB 突发（−31.7% 全帧突发）**，覆盖 dense+dw；但收益区间 0.10–0.99 s 取决于「帧是不是被冷突发串行化限住」（R4）。**条件是 G7 先在仿真里量出 CYC**，再决定要不要为它做 PnR |
| (a′) 行 halo | **RED（本片不做）** | 突发只 −4.8%、交付列 0；代价是改 tile 遍历次序或 8× 缓冲 |
| (b) dw 对角趟复用 | **GREEN（已是事实）** | 无需改动；只需在 B2 的闸门里保住 `WIDE_PASSES==nCo` |
| (c) odd/narrow | **RED（不需要做）** | 不产生额外读；倍率已被 (a) 计入 |

**B2 值不值得做在 B3 之前**：**值得，但要按 5.1 的范围**。
理由：B2b 把 B3 要流水化的突发数直接砍 **31.7%**（15.3 MB / 48.5 MB），两者正交（B2 减「笔数」、B3 减「每笔的等待」）；
B2a 完全独立、几乎零风险，且它消掉的是**最后一处 dense co-block 重读**（B1 的收尾缺口）。
反过来若先做 B3：B3 会把每笔突发变便宜，但**笔数不变** ⇒ B2 的字节收益还在，只是它的**帧时**收益会缩水
（R4 那一档不再成立）。⇒ **先 B2b 的 G7 标定、再 B2a 落地、然后 B3、最后按标定结果补 B2b 的 PnR**。

### 5.2 到 ≥0.5 fps（≤ 2.0 s/帧）的路径

| 步 | 动作 | 帧时 | fps |
|:--|:--|:--|:--|
| 0 | 现在（B1 上板） | **3.1475 s** | 0.318 |
| 1 | B2a（2 行）+ B2b（列 halo shadow） | **2.11 – 3.00 s** | 0.33 – 0.47 |
| 2 | B3：**多笔在飞**（8 个平面的 FETCH 由串行改并发，`UnitExec.scala:2322-2344`）——纯突发口径 = `1,034,244`（B2 后）× `0.8–1.4 µs` | 0.83 – 1.45 s | 0.69 – 1.2 |
| 3 | 再叠**非突发项**（14 个旁路 = 0.417 s 实测，`npu_v2_board_frame.md` §14.5；+ 权重装载/同步）⇒ **B2a+B2b+B3 的落点** | **1.2 – 2.1 s** | **0.48 – 0.83** |

若第 3 步之后仍 ≥ 2.0 s，还有两档（都不属 B2，列在这里只为「到 0.5 fps 的完整路径」）：
**B2c**（1×1 无 halo 几何：−145,296 列 / −14.2 MB 突发，但要重写 1×1 的喂列契约，§3.3）与
**dw「用满阵列」**（`mac_table` 的 B 档，−7.04 M 拍）；两者叠加可把上界压到 ~1.4 s（≥0.7 fps）。

**结论句**：
- **单靠 B2 到不了 0.5 fps**：2.11–3.00 s（0.33–0.47），最好也只有 0.47；
- **B2a + B2b + B3** 是唯一能压到 2.0 s 附近的组合：**1.2–2.1 s（0.48–0.83）**——中位在 0.5 fps 以上，
  但保守端（2.1 s）仍差 5% ⇒ 兜底靠 B2c / dw 满阵列那一档；
- B2 的正确形态是「**B2a（2 行）+ B2b（列 halo shadow，4,352 B，dense+dw 共用）**」，
  **不是** spec §4 设想的「tileBuf 留 2 行 + dw 对角趟复用」——后者一半不可行（单缓冲留不住，§3.2）、
  另一半已经是事实（§1.2）。

```python
U, _ = RA.parse_mac_table('reports/npu_v2_mac_table.txt')          # 第一张表 53 行
b = open('gen/desc.bin', 'rb').read()
S = [(struct.unpack_from('<8I', b, i * 32)[3] >> 8) & 0xF for i in range(len(b) // 32)]

def n(x): return (x + 7) // 8

def tiles(W, H, s):
    tw = 16 if s == 2 else 32                                       # TWT2 / TWT1
    for ty in range((H + 31) // 32):                                # HT_TILE = 32
        for tx in range((W + tw - 1) // tw):
            yield min(tw, W - tx * tw), min(32, H - ty * 32), tx, ty

def bands(t, W, s):
    tw, th, tx, ty = t
    step = 16 if s == 2 else 32
    base = s * (tx * step - 1)                                      # tFx / tFy
    lo, hi = max(0, base), min(s * W, base + s * tw + 2)            # [WinLo, WinHi)
    return 0 if hi <= lo else (hi - 1) // 32 - lo // 32 + 1         # 32 B band 数

T = dict(post=0, pre=0, cols=0, ar=0)
for u in U:
    s = S[u['idx']] or 1
    nc, no, dw = n(u['cin']), n(u['cout']), (u['type'] == 'depthwise')
    pf = 1 if (((not dw) and s == 1) or dw) else no      # B1 档 / dw 对角趟 / s=2 未覆盖
    cs = ar = 0
    for t in tiles(u['w'], u['h'], s):
        tw, th, _, _ = t
        cs += (s * th + 2) * (s * tw + 2)
        ar += (s * th + 2) * bands(t, u['w'], s)
    T['post'] += cs * pf * u['cin']
    T['pre']  += cs * (1 if dw else no) * u['cin']
    T['cols'] += cs * nc * pf
    T['ar']   += ar * pf * u['cin'] * 32
print(T)
```
