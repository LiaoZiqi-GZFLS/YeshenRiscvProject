# TF 卡装载：整段 CRC32 校验 + 数据相 25 MHz（2026-10-25）

**一句话**：卡上的镜像现在自带**两级 CRC32**（表头 + 每段），装载器在搬运的同时算、每个字节只经过
一次（**零额外读**）；对不上就 `errCode=7/8` 且**不放 CPU**。数据相也从 5 MHz 提到 **12.5 MHz**
（25 MHz 在这块板上实测不成立，见 §5.1）——20,910 块数据的整卡镜像约 **7.2 s**（5 MHz 时 ~17.4 s）。

---

## 1. 为什么两件事要一起做

| 现状 | 后果 |
|---|---|
| `SdLoader` 里是 `SdSpi(divFast = 9, divSlow = 499)` ⇒ 数据相 **5 MHz** | 10.7 MB 要 ~18 s；用户反馈"加载有点慢" |
| `SdSpi` **不校验卡自己的每块 CRC16**（只把 2 字节吃掉），装载器也没有任何完整性判据 | 排线（J25）上的误码会**静默装进 DDR** ⇒ 起不来/跑飞，事后无从判断 |
| 2026-10-05 曾在 25 MHz 下失败 ⇒ 当时"降速排除误码" | 5 MHz 是**规避**，不是结论；现在有了 CRC 才能安全地把速度提回去 |

⇒ 顺序是：**先有校验，再提速**。速度出问题时 CRC 会把"错"变成**响亮的 errCode**，而不是坏镜像。

## 2. 格式（块 0，全大端）

```
off 0       'Y','S','L','D'
off 4       u32 表项数 (1..8)
off 8+12i   u32 目标 DDR 地址 / u32 起始块号 / u32 块数      （既有）
off 128+4i  u32 第 i 段的 CRC32（覆盖补齐后的 块数*512 字节）  ★ 新
off 160     u32 块 0 字节 0..159 的 CRC32（保护表项本身）      ★ 新
```

* 口径 = zlib/`crc32`：**反射多项式 0xEDB88320**、初值/终值都取反、按**卡上的字节顺序**（每字节 LSB 先）。
* 覆盖范围是**补齐后**的 `块数*512` —— 硬件只看得到块数，不知道文件真实长度（零填充也算在内）。
* 生成器：`sim/mk_sd_image.py`（`build_plan()`），写完**回读**并重算两级 CRC 自证；
  `scripts/build_boot_card.sh` 直接复用同一个 `build_plan()`（原先那份重复实现已删，避免口径漂移）。

**为什么表头也要 CRC**（这是段 CRC 抓不到的一类错）：目标地址被翻一位时**数据本身完全正确**，
段 CRC 会全过，但镜像被搬到错的地方 ⇒ "CRC 全对却起不来"。表头 CRC 让这种错在 `lParse` 就失败。

## 3. 硬件实现（`src/peripheral/SdLoader.scala`）

* **流式、1 拍 1 bit**：`crcWord/crcBits/crcR`，一个字算 32 拍。
  数据相 25 MHz 时一个字 **128 拍**才到 ⇒ 4× 余量；即使 `divFast=0`（50 MHz）也还有 2×。
* `sd.io.dReady` 额外与 `!crcBusy` 相与 ⇒ **结构上不可能**在算旧字时丢新字（不是靠时序凑）。
* 表头 CRC 在**第 40 个字到货那一拍**快照（此时 `crcR` 恰为字节 0..159 的结果）；
  `lHdrRd` 等 `done && !crcBusy` 再进 `lParse`（最后一个字的 CRC 比 `done` 晚 ~32 拍）。
* 段 CRC 在**每段起点**复位（`lCopyReq && bCur===0`），在**末块**（`lWr`，且 `!crcBusy`）与
  `entCrc(eCur)` 比较。
* 新增错误码（`io.errCode` 4 位，板级 `SDR` 报文头两位直接可见）：

| errCode | 含义 |
|---:|---|
| 7 | 块 0 **表头 CRC32** 不匹配 ⇒ 不敢按这张表搬 |
| 8 | 某段**数据 CRC32** 不匹配 ⇒ 卡→装载器传输有误码/错块 |

## 4. 闸门（全部在 WSL / Verilator）

| 判据 | 期望 | 结果 |
|---|---|---|
| `sim/sdloader/run_unit.sh`（通路 A 直写，小镜像 28 块） | 放核 + DDR 逐字节 == 卡镜像 | **PASS**（13,824 B，bad=0） |
| `SD_CRC_NEG=1`（翻载荷一个字节） | `state=4 err=8`，**不放核** | **PASS**（如期失败） |
| `SD_CRC_NEG=2`（翻表项目标地址 bit8，仍 32B 对齐） | `state=4 err=7`，**不放核** | **PASS**（如期失败） |
| `run_sdloader_dma_unit.sh`（通路 B 喂 DMA 引擎） | J1..J5 全过，A/B 逐字节 | **PASS** |
| 整份交付镜像 `sd_y1_v4.img`（10,706,432 B）端到端 | `released` + 10.7 MB 逐字节 | **PASS**（10,705,920 B, bad=0；375.8M 拍，见 §5） |

两条负对照分别打到**两级 CRC**上：一个改数据（只有段 CRC 能抓），一个改表项（只有表头 CRC 能抓）。
"全绿"不算证据 —— 这两个 `err=7/8` 才是"校验真的接在通路上"的证据。

## 5. 速度

* 数据相：`SCK = 100 MHz / (2*(divFast+1))`，`divFast 9 → 1` 即 **5 MHz → 25 MHz**（SD SPI 上限）。
* 每块固定开销：CMD17（6 B 命令 + gap + R1）在 25 MHz 下只有 ~0.2 µs，相对 512 B 的 164 µs 可忽略。
* **整份交付镜像的仿真实测**（`sd_y1_v4.img` 原样喂进同一个 Verilator 装置，25 MHz）：
  `cyc = 375,837,488`（@100 MHz 系统时钟 = **3.76 s**），`RELEASED`，10,705,920 B **逐字节 bad=0**。
  其中数据相 20,910 块 × 16,384 拍 = 342.6M 拍（3.43 s），初始化（100 kHz）约 0.33 s。
* 折算 5 MHz（divFast=9）同一份镜像：数据相 5× ⇒ **约 17.4 s** ⇒ 本次省 **≈13.6 s/次启动**。
  （板上实测以串口 SDR 行的时间戳为准，见 §6。）

## 6. 上板验收（2026-10-26，`sdcrc2` + v4 卡）

* **v4 卡正常启动，8/8 判据 PASS**（SDR 帧 / OpenSBI / Linux / LiteEth / dropbear / 用户态 / 登录）。
* 装载器状态机走完 `state=2 → state=3`（err=0）⇒ **两级 CRC 在板上都通过**，CPU 被正常放行。
* **装载耗时（同一口径：SDR 报表 100 ms 一行，数 state=2 的行）**：

  | 数据相 | state=2 行数 | 装载耗时 |
  |---|---:|---:|
  | 5 MHz + 逐块 CMD17（`sdb115`） | 295 | **29.5 s** |
  | 12.5 MHz + 逐块 CMD17（`sdcrc2`） | 191 | **19.1 s**（−10.4 s / −35%） |
  | **12.5 MHz + 每段 CMD18（`cmd18`，交付）** | **70** | **7.0 s**（再 −12.1 s；累计 **−76%**） |

* 两块数据能解出同一个常量：`295/20910 = 1.41 ms/块`、`191/20910 = 0.91 ms/块`；
  减去各自的 512 B 传输时间（5 MHz 0.82 ms、12.5 MHz 0.33 ms）⇒ **每块固定开销 ≈ 590 µs**，
  与 SCK 无关。仿真是 16 µs/块（卡模型即时响应）⇒ **这 590 µs 是卡对单条 `CMD17` 的读延迟**。
* ⇒ 下一步的杠杆不是再提频，而是**多块读 `CMD18`**（见 §8）：板上实测 **7.0 s**，与仿真 7.14 s 吻合。

## 6.1 原计划的三步（已按实际调整）



1. **无卡**：串口 115200 应看到 `SDR 4xxxxx…`（`state=4`，`err=1`）随后 `YSLD` 反复 —— 证明无卡状态**可读**。
2. **插 v4 卡**：`SDR` 行走到 `state=3`（完成），随后内核日志；记录**从上电到首行内核日志**的时间，与 5 MHz 版对比。
3. 若 25 MHz 下出现 `err=8`（段 CRC 失败）⇒ 是排线误码：先降到 `divFast=3`（12.5 MHz）复测，
   不要回到"没有校验的 5 MHz"。

⚠️ **兼容性**：v4 卡与旧比特流、旧卡与新比特流**互不兼容**（旧卡没有 CRC 字段 ⇒ 新装载器报 `err=7`）。
刷比特流与写卡必须**成对**进行。

## 7. 本轮顺带查出的两个"判据/工具"问题（都已修）

1. **`build_all.sh` 的 PnR 时序闸门是恒真的（假通过）**：它 grep 的是日志里的 `All Constraints Met`，
   而这句话**也出现在 tcl 自己的 `puts "=== pnr: report_timing（判据 1：看 All Constraints Met …）==="`** 里
   ⇒ 任何违例都"通过"。实测：`sdcrc1` seed 3 的 `design summary` 明明是
   `Some Constraints Violated.`（1 条 `core_clk→phy_dq_sysclk_0` −0.005 ns），闸门照样打 `[ok]`。
   已改成读**报告本体**：`grep "Design Summary : All Constraints Met" <rtr>`，
   并做了正负对照（`sdb115` 的 rtr ⇒ PASS；`sdcrc1` seed3 的 rtr ⇒ FAIL）。
2. **`pnr -saved_outcome N` 不会在已有工程上接着跑新种子**：已有 4 个种子结果时把它改成 8，
   2 秒就"跑完"（只是把旧结果再报一遍）；直接改 `-gplace_seed` 也会被
   `Action was skipped as the flow has been run` 挡掉 —— 必须加 `-force_to_run`。
   已给 `pds/run_pnr_yeshen.tcl` 加可选入口 `YESHENMINI_PNR_GSEED=<n>`（配 `YESHENMINI_PNR_SEEDS=1`），
   一轮 ~40 min，可以逐颗试到收敛（同 netlist 的种子 0..3 是确定性的，重复跑没意义）。

这两条与本轮改动**无关**，但都会让"绿"失真 —— 记在这里，避免以后再被同一个假信号骗。

## 5.1 25 MHz 上板实测：**不成立**（2026-10-26，单变量对照）

| 臂 | 数据相 | 上板结果 |
|---|---:|---|
| `sdcrc1`（divFast=1） | 25 MHz | 初始化全过；**第一条 CMD17 拿不到数据令牌**：`SdSpi.err=6`、`lastRx=0x00` ⇒ `state=4 err=1`，CPU 不放行 |
| `sdb115`（divFast=9，旧比特流，**同一张 v4 卡**） | 5 MHz | **完整启动 8/8 PASS**（OpenSBI / Linux / LiteEth / dropbear / 用户态 / 登录提示符） |

判读：`lastRx=0x00` 是 **MISO 浮空默认电平**（`SdSpi` 文件头记过这个坑），说明 CMD17 在 25 MHz 下
根本没被卡认可，而"R1 必须为 0"的判据把浮空 0x00 当成了就绪 ⇒ 随后等 0xFE 超时。
变量只有 SCK 速率（同卡、同排线、同镜像、同装载器逻辑）⇒ **J25 排线在 25 MHz 下不可靠**，
与 CRC 无关（CRC 在这条路径上根本没轮到）。

⇒ 数据相定为 **12.5 MHz（divFast=3）**：采样余量 40 ns（卡 tODLY ≤14 ns，排线再吃几 ns），
是 25 MHz 时 20 ns 的两倍；整卡约 **7.2 s**（仍比 5 MHz 的 17.4 s 快 2.4×）。
再往上（16.7/25 MHz）必须先量排线眼图或改采样相位，并按"一次只动一个变量"上板验。

## 8. CMD18 多块读（2026-10-26）

**动机（§6 的板上账）**：每块固定开销 ≈ 590 µs 是**卡对单条 CMD17 的读延迟**，20,910 块 ⇒ ~12.3 s，
远大于 12.5 MHz 下的传输时间（6.9 s）。⇒ 把"每块一条命令"改成"**每段一条命令**"。

**实现**（`SdSpi` + `SdLoader`，镜像格式**不变**，v4 卡直接复用）：
* `SdSpi.io.nblk`：本次事务的连续块数。`nblk==1` ⇒ 仍走 CMD17，**旧的单块代码路径逐位不变**（可随时退回）。
  `nblk>1` ⇒ 追加的 6 个相位：`pCmd18 → (pTokM → pDataM → pCrcM) × n → pStopR1(CMD12)`。
  每块仍是 `0xFE 令牌 + 512B + 2B CRC16`，只是段内不再重新发命令。
* 新错误码 `SdSpi.err=7`：CMD12 的 R1 非 0 / 不来（`SdLoader` 仍统一报 `err=1`）。
* `SdLoader`：每**段**一条 `start`；块边界改由 `grp/dgrp` 在 16 组（=512B）**回卷**来划，
  `lWr` 等的是"整段尾巴"（最后一批突发落地 + CRC 算完），CRC 仍按段比较。
* `bCur` 整个删除（不再有"块内重进 lCopyReq"）。

**闸门（全绿，闸门都在 `sim/sdloader/`）**：
| 判据 | 期望 | 结果 |
|---|---|---|
| 单元正例（3 段 = 8/16/3 块，各一条 CMD18） | 放核 + DDR 逐字节 == 卡镜像 | PASS（13,824 B, bad=0） |
| `SD_CRC_NEG=1`（载荷翻一位） | `state=4 err=8` | PASS |
| `SD_CRC_NEG=2`（表项目标地址翻一位） | `state=4 err=7` | PASS |
| `SD_NEG=1`（魔数坏） | `state=4`、不放核 | PASS |
| **`SD_CMD12_NEG=1`（卡对 CMD12 回 0x04）** | `state=4`、**`sdErr=7`** | PASS（200 ms 超时后如期失败） |
| DMA 双通路 J1–J5（A/B 逐字节） | 全过 | PASS |
| 整份 `sd_y1_v4.img` 端到端（仿真） | 放核 + 10.7 MB 逐字节 | **PASS**：713,932,456 拍 ≈ **7.14 s**，bad=0 |

仿真里没有卡延迟 ⇒ 7.14 s 就是 12.5 MHz 的**传输地板**（理论 6.85 s + 多块间 token 间隙 + CMD12 收尾）。
板上若仍接近这个数，说明 CMD18 把"每块 590 µs"确实拿掉了；若明显更大，就是卡的**块间间隙**成了新常数，
下一条杠杆是提 SCK（需先解决 25 MHz 的信号完整性问题，见 §5.1）。

## 9. 上电即用：位流固化进配置 flash + 配置时钟提速（2026-10-26）

### 9.1 固化（掉电不丢）

用 `cam2lcd_200mini/flash_spi.bat <sbit>`（PDS 的 `cfg_gen_sfc` + `cfg_jtag_flash_erase/program/verify`
+ 回读 `fc /b`）。实测：erase 29 s / program ~220 s / verify 76 s / readback 76 s，整轮 ~6 min。
判据 = 回读与输入镜像**逐字节相同**（`[5/5] readback MATCH`）。

### 9.2 配置时钟：2.99 MHz → 11.76 MHz（4×）

PDS 的合法档位：`66.66M 50M 40M 33.33M 25M 22.22M 15.38M 11.76M 9.09M 6.06M 2.99M`（默认 2.99M）。
加载时间 = 9,188,552 B × 8 ÷ f：

| 配置时钟 | 理论配置时间 |
|---:|---:|
| 2.99 MHz（默认） | 24.6 s |
| 6.06 MHz | 12.1 s |
| 9.09 MHz | 8.1 s |
| **11.76 MHz（当前固化）** | **6.25 s** |
| 15.38 MHz | 4.8 s |
| 22.22 MHz | 3.3 s |

**实测（11.76 MHz，断电冷启动，无 JTAG）**：串口从 `SDR` 开始 → 71 行（SD 装载 7.1 s）→
`state=3` → `Linux version` → `Y1CAM-BOOT pid=96`（3.66 s）→ `login:`；到登录约 **17–18 s**。
⇒ 配置时钟取 11.76 MHz 是**已验证**的交付点（再往上要重新验冷启动可靠性）。

**位流压缩无效**：`-compress_bitstream true -optimize_compress true` 只把 9,188,552 → 9,129,392 B（−0.6%），
这条杠杆对本设计不成立。
