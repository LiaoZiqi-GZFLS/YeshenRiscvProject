# G4：`Npl ≤ 4` 时一行两个 band 合成一个 64 B SG 项

日期：2026-10-25　状态：**单元闸门 PASS（含路径覆盖）**，等 PnR + 上板　前置：`b1sg` 交付（1,262.4 ms）

## 1. 病根（实测账）

`Conv_0`（真表唯一的 `C_in=3` 层）在 60 MHz 的逐单元表里 **150.8 ms / 736 ns/px**，
而它的交付字节只有 ~1.35 MB（地板 56 ms @24.2 MB/s）⇒ **2.7× 地板**。

RTL 账（`UnitExec.scala` 的 tiled `wx` gather）：

- 一个 SG 项 = **一个平面的一个 32 B band**（`sg_beatsM1=3`），一批最多 8 项；
- `C_in=3 ⇒ Npl=3` ⇒ 一批只有 **3 项 = 96 B**（4 笔在飞时仍按 1 个 LAT 摊）；
- s=2 的 tile 窗口 = `2·16+2 = 34` 列 ⇒ **每行 2 个 band = 2 个批**。

算：320×320 输出、tile 16 宽 ⇒ 20×10=200 tile，每 tile 66 行 ⇒ **13,200 行**；
`13,200 × 2 × 5.12 µs（LAT=640@125MHz）= 135 ms` —— 与实测 150.8 同量级 ✔。
对照：dw 层 Npl=8 ⇒ 8 项/批 ⇒ 实测贴 24.2 MB/s 的 **1.07×**。

## 2. 设计（只动 `TILING` 的 tiled gather，`TILING=false` 逐字不变）

1. **`wxTwoB`**（`go` 那拍锁存）= `(C_in ≤ 4) && (输入行宽 % 64 == 0)`。
   · `C_in ≤ 4` ⇒ Npl ≤ 4，2×Npl ≤ 8 项，一批装得下两个 band；
   · 行宽 64 对齐 ⇒ 平面基址与 `+32` 的 band 同属一个 64 B 块（`Conv_0`：输入 640 宽 ✔）。
2. **一个项读 64 B**：`sg_beatsM1 = 7`（8 拍，仍是 4 的倍数、64 B 对齐）⇒ 同一行的两个 band 一次取回。
3. **账本按 64 B 对齐**：`wxBB / wxPBB(p)` 在两 band 模式下 `& ~63`（否则 `& ~31`）；
   `wxPNE(p)` 的"已装"判据因此自动覆盖两个 32 B band（**不新增第二本账**）。
4. **缓冲不扩**（`xwBuf` 仍 32 项）：两 band 档只用于 `Npl≤4` ⇒ `plane*8 + wxFB2*4 + beat ≤ 31` ✔；
   落点/读侧都按模式选索引（两 band：`plane*8` / `PIDX(5:3)`；否则 `plane*4` / `PIDX(4:3)`）。
5. 地址仍是**纯加法**（`+32` 落在同一 64 B 块内），不新增 `tInPixW·p` 乘链 ⇒ npu 头号路径零影响。

预期：`Conv_0` 每行 2 LAT → **1 LAT** ⇒ 150.8 → ~85 ms ⇒ 整帧 **−5~6%**（1,262 → ~1,195 ms）。

## 4. 风险

| 风险 | 对策 |
|---|---|
| 64 B 项跨行/跨平面读（行尾） | 只多用字节、不改语义；读取端只取 `PIDX(2:0)` 的字节，越界部分不参与计算 |
| `tInPixW % 64 != 0` 的层被误开 | `wxTwoB` 的 latch 条件显式检查 `tInWi(5:0)==0` |
| ~~缓冲翻倍~~ | **已否决**：首版把 `xwBuf` 翻到 64 项 ⇒ 读口变 64:1 mux + 多 2K FF ⇒ seed0 时序 **−1.293 ns**（b1sg 是 +0.109）。改成"按模式切索引、缓冲仍 32 项"后重跑。 |
| 两 band 模式下 `wxBndB` 语义变 | 账本比较对象全部改成 64 B 对齐值（`wxBB/wxPBB` 同源）⇒ 自洽 |

## 5. 与 G3（重叠）的关系

G4 解决"**批太瘦**"（Npl 小 ⇒ 每 LAT 只搬 96 B）；G3 解决"**fill 与算零重叠**"。
两者互补：G4 打 `Conv_0`，G3 打 conv1x1（fill 373 ms / 算 212 ms）。

## 6. 单元闸门结果（2026-10-25，`B1_FAST=1` 档）

```
[conv15/pos] MISMATCH=0  GATHER_BYTES=73984 GEXP=73984 GB_OK=1     （32 B 档，C_in=32）
[c4_64/g4]   MISMATCH=0  GATHER_BYTES=9248  GEXP=9248  GB_OK=1     （64 B 档，C_in=4）
OK: c4_64 G4_SEEN=1（64 B 项档确实启用，非空跑）
OK: conv15 G4_SEEN=0 / c64_40 G4_SEEN=0（Npl=8 层不误开 64 B 档）
[mut] GATHER_BYTES=295936（期望 295936）GB_OK=0（期望 0）⇒ 负对照只翻 8 倍计数
RESULT: PASS
```

**为什么要 `G4_SEEN`**：只判"逐字节对"不能证明 64 B 档真的被走到（32 B 路径也会对）。
TB 里加了 `always @(posedge clk) if (dut.wxTwoB) g4_seen<=1;`，闸门要求
`c4_64 ⇒ 1`、`conv15/c64_40 ⇒ 0`（模式泄漏也要红）。

注：`B1_FAST=1` 只把两个大作业的形状缩到 32×64（**同代码路径**，省仿真时间）；黄金/GEXP 按
新几何重算，判据不放松。全尺寸档仍是 160×160 / 40×40。

## 7. 时序回归与修正（2026-10-25）

- 首版（`g4nb`）：`xwBuf` 32→64 项。dev_map FF 115,356 → 117,409（+2,053），PnR **seed 0
  `Setup(Slow) = -1.293 ns`**（全部违例在 `npu_clk`：1130 端点 / TNS -340 ns）⇒ **判否**。
- 根因：64 项读口 = 64:1 数据 mux（比 32:1 深一级）+ 2K FF 的布线，而 NPU 原本只剩 +0.109 ns。
- 修正：`Npl<=4` 意味着两 band 档最多 4 平面 x 8 字 = **32 项** ⇒ 缓冲**不必扩**；
  改成"按 `wxTwoB` 切索引"（两 band：`plane*8 + fb2*4 + beat`，否则 `plane*4 + beat`），
  读口仍是 32:1。§6 的闸门在修正后**仍全绿**（`c4_64` 逐字节 + `G4_SEEN=1`；无泄漏；负对照有牙），
  且 `TILING=false` 三网表 md5 **未变**（不需要重锚）。PnR 以 tag `g4nb2` 重跑。

## 8. 判决（2026-10-25）：**G4 不采纳，已干净回退**

| 版本 | 关键结构 | PnR seed 0 `Setup(Slow)` | 判 |
|---|---|---:|---|
| b1sg（交付） | `xwBuf` 32 项，无两 band 档 | **+0.109**（npu 60.39 MHz） | 保留 |
| `g4nb` | `xwBuf` 64 项（平面×8） | **-1.293**（1130 端点全在 `npu_clk`，TNS -340） | 否 |
| `g4nb2` | `xwBuf` 32 项 + 按模式切索引 | **-0.798** | 否 |

根因：NPU 在 60 MHz 只剩 **+0.109 ns**。G4 要在 `wxPBB`（→ `sg_addr`/账本比较）与喂列读口上
各加一层模式选择，代价 ≥0.9 ns ⇒ **这条路径没有余量再吃任何地址/读口改动**。

处置（净值结算）：

- TB 的 `G4_SEEN` 探针、闸门的 `c4_64` 作业与判据全部撤掉。
- **回退的自证**：重生成后 `TILING=false` 三网表 md5 = `451102f3 / 0f549d2e / dbfc18db`
  —— 与 b1sg 交付构建**逐字节相同**；`B1_FAST=1` 闸门复跑 **RESULT: PASS**（两个正对照逐字节 +
  负对照只翻计数）。
- 交付物不变：板上仍是 `b1sg`（`c408792f…`，1,262.39 ms / 0.792 fps）。
